## Open question (escalation)

The bootstrap (`2026-04-30-001-repo-bootstrap`) did not install
`@types/node`. With strict TS settings, the `process` global is therefore
untyped and `npm run typecheck` fails — but the logger's acceptance
criterion *also* says "no external dependencies beyond what bootstrap
installed."

These conflict. Three plausible paths, none of which I am authorized to
choose unilaterally per drift rule 3 ("no new dependencies without
escalation"):

- **(A) Add `@types/node` as a devDependency.** It is a type-only
  package (no runtime code) and is effectively required for any
  TypeScript Node project. Most natural reading of the spec, since the
  "no external deps" prose names runtime logging libs (winston, pino,
  bunyan). Probably what the bootstrap should have included.
- **(B) Add a minimal local `declare` block** for `process.env` and
  `process.stdout.write` inside the logger module, avoiding the dep
  but at the cost of a custom shim.
- **(C) Pause this item; first update the bootstrap (001) to include
  `@types/node`** (a tiny follow-up backlog item) before unblocking the
  logger.

**Best guess: A**, with confidence ~85%. `@types/node` is to TS-Node
what `typescript` itself is — a non-runtime build prerequisite, not a
"dependency" in the spirit the spec is forbidding.

**Why I escalated rather than guessing:** drift rule 3 names this
exact case ("If the spec doesn't name a library, escalate"). The
acceptance criterion explicitly mentions bootstrap-installed deps as a
ceiling, so adding any new dep — even a type-only one — needs founder
sign-off. Better to escalate than to invent a workaround that ties
future TS work to a non-standard pattern.
