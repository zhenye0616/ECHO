# Agent Run: Terminal intake card — stations 1–3 live end-to-end, zero Slack dependency

## What I Implemented

A new standalone tool `tools/intake-terminal.ts` (`npm run intake:terminal`) that
renders the Granola meeting → signals → classified decision-packet candidate
pipeline as a plain-text/ANSI card on stdout, with **zero changes to
`src/enrich/**`**. It imports and drives the existing mechanism
(`runGranolaIntakeBridgeOnce` / `startGranolaIntakeBridge`) and injects a stdout
`postSeed` in place of the Slack POST — the seam identified in the spec
(`granola-intake-candidates.ts:87,658`). Candidate selection, classification,
per-note capping, and the durable seed-state machine all run unmodified.

- **`--once`** (default): one tick, one card per posted seed, then a status line
  (notes / candidates / cards printed / skipped / failed / classifier errors),
  and an exit code (0 on ok; 1 on fail-fast / brain-unavailable / disabled).
- **`--watch`**: reuses `startGranolaIntakeBridge`'s interval + debounce +
  single-flight. Brain preflight is lazy per tick via the bridge's
  `runSignalsFirst` start-of-pass seam (the only per-tick hook exposed); every
  tick that finds the brain unavailable prints a per-tick skip status line and
  never crashes. Ctrl-C stops cleanly (SIGINT/SIGTERM → `handle.stop()`).
- **Config (AC3)**: `buildTerminalIntakeConfig` constructs `GranolaIntakeConfig`
  directly (enabled, `terminal` channel sentinel, unused bot token) — no
  Slack-shaped env required. Non-Slack knobs (internal domains, owner map,
  lookback, caps) still come from the same env; a `terminal` defaultOwner
  fallback keeps owner-unresolved notes from being dropped so candidates surface.
  Classifier default is the real `runBrain` path
  (`ECHO_GRANOLA_INTAKE_BRAIN ?? ECHO_CEO_BRAIN`), injectable for tests.
- **Seed-store isolation + fail-fast (AC4)**: default store is a dedicated file
  `~/.echo/state/granola-intake-seeds.terminal.json`, overridable via
  `--seed-store <path>`. Before rendering any card the tool creates the parent
  dir and confirms write access; an uncreatable/unwritable path fails fast with a
  clear message + nonzero exit before any card prints.

## Decisions Made During Implementation

### Decision 1: `--once` real path routes through `startGranolaIntakeBridge(runOnStart:false).run()`, not `runGranolaIntakeBridgeOnce` directly
- **Why:** `runGranolaIntakeBridgeOnce` requires a `classify` dep, but the real
  brain classifier (`defaultClassifierFromBrain` + `resolveBrainClassifierConfig`
  + `buildClassificationPrompt` + `parseClassifierAnswer`) is **not exported**.
  Reconstructing it would duplicate classification logic — forbidden by AC1 /
  "Out of Scope". Letting the bridge build the classifier (via `run()` →
  `runGranolaIntakeBridgeOnce` internally) reuses it verbatim. The
  injected-classifier path (tests) calls `runGranolaIntakeBridgeOnce` directly.
- **Worth founder review?** Minor. It satisfies AC1's "import and call
  runGranolaIntakeBridgeOnce / startGranolaIntakeBridge" (both imported; the once
  path calls the former with an injected classifier, the real path calls the
  latter which calls the former). No seam gap escalated because reuse is clean.

### Decision 2: `--watch` per-tick brain skip line uses the bridge's `runSignalsFirst` seam
- **Why:** AC3/AC5 require a tick-level "skipped: brain unavailable" line while
  reusing the bridge's own interval. The bridge exposes no per-tick result hook
  and no `preflight` seam (unlike the signal worker's f19dc419). Its only
  start-of-pass injectable is `runSignalsFirst`; I use it to run the lazy
  preflight and print the skip line each tick. On the real path the bridge's own
  classifier self-fails per note when the brain is down (skip line already
  printed); on the injected path a gating wrapper throws so the stub never posts.
- **Worth founder review?** Slightly unconventional use of `runSignalsFirst`
  (documented in the tool header). No mechanism change; no seam gap.

### Decision 3: "subject" in the card is best-available, not canonical_subject
- **Why:** The `postSeed` seam only receives `(channel, text)`. `parseSeedMarker`
  recovers candidate key, note id, meeting title, quote, and intake fields — but
  the signal's `canonical_subject` is not carried by the seed message. The card
  shows Subject = request field ?? clientProject ?? meeting title, plus the
  derived signal type (parsed from the candidate key) and candidate key. All
  AC2-listed fields except canonical_subject are surfaced verbatim.
- **Worth founder review?** No — canonical_subject is simply not on this seam;
  surfacing it would require a src/enrich change (out of scope).
