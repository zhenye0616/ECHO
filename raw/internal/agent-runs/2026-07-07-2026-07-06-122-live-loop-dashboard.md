## Run 1

### What I implemented

A read-only, self-refreshing local dashboard over the team loop's health,
reusing item 117's in-process doctor loop report and item 120's worker
heartbeats. Last-inch rendering only — no new collectors, daemon changes, or
persisted state.

- `tools/loop-dashboard.ts` (new, the only substantive file): a `node:http`
  server bound to 127.0.0.1 only, following the `tools/serve-trace.ts` shape.
  - **In-process reuse (AC2 primary path):** calls the exported
    `buildLoopReport(opts, ctx)` from `src/cli/commands/doctor.ts` — NOT
    `buildDoctorReport` — so the dashboard never runs the MCP probe, the
    codex-adapter child, or the agent probes. This keeps the read-only + no-MCP
    + no-network guarantees trivially true. No child fallback is wired (in-process
    only), so the AC5 doctor-fail-soft coverage tests the in-process degraded
    path (an injected builder that throws / never resolves), per the spec's
    r3-codex-F1 allowance.
  - **Heartbeats (AC2b):** iterate item 120's exported `EXPECTED_WORKERS`
    (`GRANOLA_SIGNALS_WORKER`, `DRIFT_SWEEP_WORKER`,
    `GRANOLA_INTAKE_BRIDGE_WORKER`) — never a `worker-heartbeat-*` glob — so an
    absent expected worker still surfaces as an `{ error }` entry rather than a
    dropped key. A malformed file is likewise an `{ error }` entry.
  - **Single-flight throttled provider (AC2):** `createStatusProvider` holds a
    cached body + `computedAt`; a poll within `MIN_RECOMPUTE_INTERVAL_MS` (10s)
    is served fresh from cache; past that a warm poll stale-serves the cache
    immediately while a background recompute runs; a cold poll (no cached doc)
    JOINS the one in-flight computation. `computeStatusBody` is fail-soft
    (never rejects), so cold joiners always receive a contract-shaped document —
    a timeout/failure yields the degraded/`unknown` skeleton, never `undefined`,
    a 500, or a stall. At most one computation is ever in flight.
  - **Port precedence (AC1):** `--port <n>` → `ECHO_LOOP_DASHBOARD_PORT` →
    default `38480` (the single named constant `DEFAULT_LOOP_DASHBOARD_PORT`).
    An invalid explicit port (non-numeric / <1 / >65535 / `--port` with no
    value) throws → fatal one-line stderr + non-zero exit; never a silent
    default fallback (invalid ENV is fatal too).
  - **Entry guard (AC1, item 121 precedent):** `process.argv[1] ===
    fileURLToPath(import.meta.url)`; importing the module never starts the
    server.
  - **The page (AC3):** one self-contained HTML doc (inline CSS/JS, zero
    external requests) that polls `/api/status` every 15s and renders stations
    1 capture, 2 signals, 3 packet, 4 record, 6 drift + serving identity/dist
    staleness. Status reuses doctor's `ok|degraded|disabled` vocab plus
    `unknown` for the fail-soft case; degraded/disabled/unknown get distinct
    card + chip classes so faults are visually unmissable. Station 6 (drift) is
    heartbeat-driven (no doctor section exists for it) and renders even when the
    doctor computation fails.
- `package.json`: `loop:dashboard` npm script → `vite-node --script
  tools/loop-dashboard.ts` (matches item 121 / `eval:retrieval`; `--script` is
  required for the argv[1] entry check to hold).

### Decisions made during implementation

- **`buildLoopReport` over `buildDoctorReport`.** The dashboard needs exactly
  the loop section (stations 1-3 + serving); `buildDoctorReport` additionally
  performs an MCP `initialize` probe (network), a codex-adapter child spawn, and
  agent probes — all of which would violate AC4's "no MCP calls, no network
  beyond serving localhost". `buildLoopReport` is purely read-only (checkpoint /
  seed-store / heartbeat file reads, `lsof`/`ps` serving detection, storage
  SELECTs gated on `existsSync`). I replicate `buildDoctorReport`'s read-only
  serving-context computation (`resolveMcpPort` + `resolveDataDir` + pid-lock)
  to build the `ctx` argument.
- **AC4 no-write test approach.** SqliteStorage's constructor opens read-write,
  sets the WAL pragma, and migrates — opening a real db therefore creates
  `-wal`/`-shm` and is NOT byte-identical. Item 117's own read-only contract is
  "never CREATE/migrate a missing db" (the `existsSync` gate), and its
  read-only test asserts a missing db is not materialized. I follow that exact
  precedent: the AC4 byte-identical test fabricates every read input
  (checkpoints, seed store, heartbeats) but leaves the atom db absent, runs one
  full `computeStatusBody` cycle over the SHIPPED in-process path, and asserts
  ECHO_HOME is byte-identical + the db was not created. The spec's AC4 escape
  hatch explicitly blesses in-process reuse here.
- **Station 4 (record) = team-decisions preview count.** The 117 loop report
  carries `teamDecisionsCount` on station3; I surface it as station 4. A count
  of 0 is expected (not a fault) → `ok`; `null` (db unavailable) → `unknown`.
- **Station 6 (drift) is heartbeat-only.** There is no 117 doctor section for
  drift; its status IS the drift-sweep heartbeat (incl. `disabled` reason + last
  sweep counters). Heartbeats are read independently of the doctor computation,
  so a doctor timeout/failure never blanks station 6.
