## Run 1

### What I implemented

Card-derivation observability for the Granola → Slack intake bridge (station 3).

1. **AC1 — card atom.** `runGranolaIntakeBridgeOnce` now appends one
   `derived:intake-cards` atom on every successful post, in the channel-agnostic
   bridge path (not the terminal tool). `content` = the exact rendered card text;
   `metadata` = classified fields, `candidate_key`, `signal_refs`, `note_id`,
   `channel_id`, seed-status timestamp, `slack_ts`, and the embedded
   `classifier_run`. `dedupe_key = granola:card:<candidate_key>`. Idempotent under
   re-posts via the existing seed-store duplicate-suppression (a `posted`/`failed`
   record is skipped at claim, so the append never re-runs). Atom-write failure is
   fail-soft (never breaks posting) BUT durably marked: the seed record gains
   `card_atom_status ∈ {written,failed}` (+ `card_atom_error`), written in the same
   `markPosted` update; a duplicate-suppressed rerun never reaches `markPosted`
   again, so a `failed` marker is never cleared.

2. **AC2 — retrieval correlation.** New `runBrainWithRetrievalCapture` in
   `brain.ts` wraps the brain child with a per-run localhost recording proxy in
   front of the child's scoped `ECHO_MCP_URL` (the same env seam the CEO responder
   uses). The proxy forwards every request byte-for-byte to the real daemon (so it
   never alters what the classifier sees) and tees a coarse summary of each
   `tools/call` exchange. Persisted `classifier_run` shape: `run_id`, `binding`,
   `model?`, `started_at`/`completed_at`, and the REQUIRED tri-state
   `capture_status ∈ {ok, zero_retrievals, capture_failed}` (`retrievals[]` when
   ok; `capture_error` when failed). Reachable one hop from the card atom via
   `classifier_run.run_id`. Capture is fail-soft: a proxy that can't start or
   errors surfaces `capture_failed`, never a fabricated `zero_retrievals`.

3. **AC3 — trace surface.** `tools/trace-card.ts` + npm script `trace:card`
   (`vite-node --script`, 121 precedent) guarded with the house `import.meta`
   entry check. Input: a `candidate_key` (or `--note <note_id>`). Walks card atom →
   classifier run (tri-state rendered distinctly) → consumed signal atom(s) → raw
   source atom(s). Every stage prints what exists and names what is absent; a
   pre-123 card (no card atom) still walks the seed → signal → raw remainder.
   Reports a `card_atom_status: failed` marker (or a missing card atom) as a
   PROVENANCE LOSS banner.

4. **AC4 — strictly read-only.** The trace writes nothing. SQLite open is gated on
   `existsSync(dbPath)` (SqliteStorage's constructor creates+migrates a missing db);
   the seed store is read via its read-only accessors. Tests assert a byte-identical
   scratch filesystem including the no-db-file case, plus a no-atom-mutation check
   over a present db.

5. **AC5 — tests.** Fixture-driven, no live daemon: card-atom emission + refs +
   embedded run; idempotent re-post; write-failure not silently masked (marker +
   marker-survives-rerun); all three capture states persisted + distinguishable;
   trace full-chain + three capture states + missing-stage fail-soft; entry-guard
   regression (spawned vite-node); no-write.

### Decisions made during implementation

- **Seed-store file edit is forced by AC1, outside the PROVISIONAL files_to_modify
  list — flagged, not blocked (121 precedent).** AC1 explicitly requires "the seed
  record gains a persisted `card_atom_status` field … written in the same
  seed-store update". That record type + `markPosted` live in
  `granola-intake-seed-store.ts`, which the PROVISIONAL list omitted. There is no
  way to satisfy the literal AC without editing it. This mirrors item 121, where a
  forced package.json change outside the provisional list was flagged and
  founder-ratified. The new `markPosted` arg is optional, so no other caller breaks.

- **Capture mechanism = recording proxy (AC2's "reuse-first" option 2).** The
  alternative — a per-run correlation id stamped by the daemon's coord/identity
  layer — would require daemon/MCP-server changes (retrieval READS are not logged
  to the store today; the coord identity layer is emit-scoped), all outside
  files_to_modify. The proxy lives entirely in `brain.ts` and rides the existing
  `ECHO_MCP_URL` child-env seam. It forwards byte-for-byte, so it cannot alter the
  classifier's inputs (satisfies "records the derivation, does not alter it"), and
  is fail-soft to `capture_failed`.

- **Classifier signature is a backward-compatible union** (`Candidate[] |
  { candidates, run }`). Legacy array-returning classifiers keep working; a legacy
  result yields an honest `capture_failed` run ("classifier did not report
  retrieval capture"), never a fake ok/zero. This kept the blast radius to the one
  count-assertion test above; all other bridge-driving tests were untouched.

- **`signal_refs = [candidate_key]`** — a card derives from exactly the one signal
  whose dedupe_key IS the candidate_key (per the spec's "candidate_key IS the
  signal dedupe_key"). The trace walks card → signal via this.
