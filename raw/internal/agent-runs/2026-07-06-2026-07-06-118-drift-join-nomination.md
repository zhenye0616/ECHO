## What I implemented

Built the drift join from silent exact-equality (near-zero recall) into an
AI-free nominate-then-confirm step with observable misses.

- **AC1 — separator folding in the one shared normalizer:** `normalizeSubject`
  (`src/util/subject.ts`) now folds `_`, `-`, and runs of them to a single space
  before the existing lowercase/trim/whitespace-collapse, so
  `openai_investment_terms`, `openai-investment-terms`, and
  `openai investment terms` produce the identical key. Subjects with no separators
  are byte-unchanged (dedupe_key stability preserved); separator-only-differing
  subjects now collapse (documented in the doc comment as intended).
- **AC2 — pinned extraction format:** `buildExtractionPrompt`
  (`granola-signals.ts`) adds one instruction line telling the extractor to emit
  `canonical_subject` as a space-separated lowercase noun phrase (no snake_case /
  camelCase / separators). Prompt text only — no schema, parse, or validate
  change; `normalizeSubject` remains the authority.
- **AC3 — nominate-then-confirm join:** replaced the exact
  `decisionBySubject.get(...)` with a deterministic nominator. For each statement
  it scores every recorded decision by Jaccard over normalized word sets, nominates
  those at/above `DRIFT_NOMINATION_JACCARD_THRESHOLD = 0.2` (exported), capped at
  `DRIFT_MAX_NOMINATIONS_PER_STATEMENT = 5` (exported) by a TOTAL tie-breaker
  (score desc → normalized subject asc → dedupe_key asc). Decision token sets are
  computed once per tick. Each nominated `(decision, statement)` pair goes through
  the EXISTING `judgePair`/brain path with the unchanged
  `driftPairKey(decision.dedupe_key, statement.statement_dedupe_key, judgeVersion)`,
  so multi-nomination is checkpoint-safe and the judge budget / checkpoint / delivery /
  watermark state machine are untouched. No embeddings, no LLM in the nominator
  (seam decision 19).
- **AC4 — misses become data:** per-tick counters `statements_seen`,
  `statements_nominated`, `statements_no_candidate`, `decisions_scored` added to the
  `DriftSweepResult` ok branch and the `drift_sweep_ok` log. Each no-candidate
  statement emits a `drift_nomination_miss` log naming the top below-threshold
  decision subject + score (selected by the SAME tie-breaker), or an explicit
  "no decisions to score against" note when the decision set is empty.
- **AC5 — end-to-end:** a separator-only-differing pair now joins and is judged
  (would have missed under 114); a topically-continuous pair (openai sponsorship /
  openai investment terms, 0.25) nominates and is judged; an unrelated pair is a
  logged near-miss, never judged. The 114 idempotency/watermark/at-most-once tests
  pass unchanged.

## Decisions made during implementation

1. **Re-normalize subjects at join time for the token sets.** `subjectTokens`
   runs the subject through `normalizeSubject` before splitting on whitespace, so
   older stored subjects (written before AC1) still get separators folded at scoring
   time — the retroactive-recall fix, idempotent for fresh atoms.
2. **Tie-breaker on score uses exact equality then subject/dedupe.** Equal
   integer-ratio Jaccard scores are identical IEEE doubles, so `a.score !== b.score`
   is a safe tie test; the tie fixture (7 tied `common a`..`common g`) asserts the
   deterministic five (`a`..`e`) survive the cap.
3. **The 3 measured study pairs.** The decision record names the openai pair
   explicitly but does not enumerate the other two verbatim, so `tests/util/subject.test.ts`
   uses the named openai pair plus two real-shaped separator-only pairs
   (`pricing_tier`, `slack_bot_token` families) — the testable claim is that
   separator-only-differing word-identical subjects normalize equal, which these
   prove across `_`, `-`, runs, and mixed.
4. **Kept the full decision pool (not window-bounded).** Matches 114's accepted
   full-scan-per-tick; `decisions_scored` surfaces the pool size so cost growth is
   visible before the `statements_seen × decisions_scored` work overruns the interval.
