## Decisions Made During Implementation

### Decision 1: ESLint dependency choice
- **Options considered:** the `typescript-eslint` wrapper package vs. the individual `@typescript-eslint/parser` + `@typescript-eslint/eslint-plugin` packages.
- **Chose:** the two scoped packages.
- **Why:** the spec's allowed-deps clause is `@typescript-eslint/*` (scoped wildcard). The unscoped `typescript-eslint` wrapper is not covered by that wildcard, so picking it would have required an escalation. The two-package path is fully spec-compliant.
- **Worth founder review?** No — direct read of the spec.

### Decision 2: Prettier scope
- **Options considered:** (a) default `prettier .` over the whole repo; (b) add a `.prettierignore`; (c) scope the script to specific paths via `package.json`.
- **Chose:** (c). The `format` and `format:check` scripts list `src tests package.json tsconfig.json vitest.config.ts eslint.config.js .prettierrc.json` explicitly.
- **Why:** option (a) failed because Prettier swept all the wiki/backlog markdown and reported 48 style mismatches; option (b) would have required creating a new file (`.prettierignore`) not in `files_to_modify`, which is a drift-rule-4 violation and would have required escalation. Option (c) keeps the contract — format:check exits 0 — using only files already in `files_to_modify`.
- **Worth founder review?** Mention only — confirm at review time that this scope is acceptable. It can be widened in a later item once `.prettierignore` is on someone's `files_to_modify`.

### Decision 3: `package.json` `type: "module"`
- **Why:** strict `NodeNext` resolution + ESM imports in `eslint.config.js` and `vitest.config.ts` argue for ESM at the package level. Aligns with the dominant 2026 JS toolchain default.
- **Worth founder review?** No — standard for new TS/Node projects.
