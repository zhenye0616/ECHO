### AC2 — `skills/review-pending.md` vendor-neutralization

  - Per-child sandbox = `workspace-write` scoped to the item's per-item worktree (`-C <worktree>`); main repo is OUTSIDE each child's write surface.

  - Sidecar write happens in the single-threaded orchestrator path (children never touch the main repo).
  - Parse-failure semantics: missing review file OR `rc≠0` OR missing required section → copy the child's `{stdout, stderr, review.md}` triple to `raw/internal/queue-errors/<ISO-ts>-review-pending-<item-id>/` BEFORE the `RUN_DIR` trap fires, log a queue-errors row that names the specific missing sections + `rc` + first 2KB of stderr, never silently substitute defaults.

### AC4 — Deployment helper + AGENTS.md

- `tools/install-codex-adapters.sh` (mode 0755). Modes: `--symlink` (default), `--copy`, `--dry-run`. Pre-flight `mkdir -p` for `$HOME/.codex/{,skills,.echo-staging,.echo-locks}`. Refuses on unwritable HOME with `HOME` named in the diagnostic.
- Stale-staging cleanup uses `find … -mindepth 1 …` to preserve the staging root.
- Per-skill atomic-mkdir lock at `$HOME/.codex/.echo-locks/<name>`; writes `pid` + `timestamp` files immediately after acquisition. Trap removes lock on EXIT (lock array, per-skill cleanup).
- **Three-factor stale-lock gate** (recovery requires ALL THREE):
  1. **Age:** readable timestamp `now - ts > 600s`, OR `lock-dir mtime > 600s` if timestamp file is missing/non-integer (with a stderr warning naming the missing/corrupted case).
  2. **PID liveness:** `kill -0 <pid>` returns non-zero. If pid file is missing/non-integer, fall through to age-only check with a loud `manual recovery may be needed` warning.
  3. **No other install process for this skill:** `pgrep -f install-codex-adapters.sh` filtered to processes whose argv mentions the skill name.
- Pre-install target probing classifies `$HOME/.codex/skills/<name>` as absent / managed-symlink (real target equals repo adapter dir) / managed-copy (`.echo-managed` sentinel present) / non-managed-symlink / non-managed-directory / regular-file. Refuses anything but absent + managed-*; managed-symlink ↔ managed-copy mode switches rewrite cleanly (probe → rm-then-create).
- `--copy` mode stages under `$HOME/.codex/.echo-staging/<name>-$$` (OUTSIDE the live skill discovery root), writes sentinel first (`synced_from_commit=<sha> + synced_content_sha256=<sha256(adapter/SKILL.md)> + synced_at + source`), then `cp -R` adapter contents, then atomic `mv` into place. Content-hash sentinel (not HEAD-SHA, per R8 patch) means stale detection survives unrelated commits and catches uncommitted skill edits.
- `AGENTS.md` Canonical Reads gains a "Codex skill discovery" subsection covering both install modes + the snapshot-refresh constraint on `--copy`.

## Notable implementation decisions

1. **Canonical frontmatter parsed line-by-line, not via PyYAML.** As noted in AC1 section. Adapter frontmatter is still strict YAML (round-trips through `yaml.safe_dump`); only the canonical-read path is lenient. The spec did not explicitly anticipate this corner — the test case `YAML-safe serialization for tricky descriptions` exercises the OUTPUT-side YAML safety, which is what AC1's R1 codex F1 patch required. No canonical files were edited.
2. **Sentinel records BOTH `synced_from_commit` AND `synced_content_sha256`.** AC3's named test `--copy install sentinel records synced_from_commit` (carryover from R7) and AC4's R8 patch (content-hash for staleness detection, not HEAD-SHA) both apply — written both lines into the sentinel so both contracts are satisfied. `tools/sync-skills.sh --check` reads `synced_content_sha256` for the stale-copy warning; `synced_from_commit` is informational only.
3. **Worktree-scoped `workspace-write`, not main-repo.** The AC2 codex notes were emphatic: per-child sandbox is `workspace-write -C <worktree>` (each item's per-item worktree, NOT the main repo). I made the prose explicit on this point and on the disjoint-worktree non-race property; the actual orchestrator implementation is OoS.
4. **`set +e` subshell wrapping** for child invocations under orchestrator's `set -euo pipefail` is documented in the codex binding-specific notes. Without it, codex's non-zero exit kills the subshell before the rc-write line runs and the orchestrator drain sees a missing rc.
