# Run 1 — Claude Code extractor

## What I implemented

- `src/capture/extractors/claude-code.ts`:
  - `extractClaudeCodeTurns(jsonlPath, lastByteOffset)` reads the session
    JSONL from the given byte offset to EOF, parses complete lines (anything
    past the last `\n` is left for the next call), pairs consecutive
    text-bearing user / assistant lines into turns. tool_use and tool_result
    blocks are stripped from content but set `had_tool_use=true` on the
    surrounding turn. Returns `{turns, newOffset}`.
  - `startClaudeCodeExtractor(storage, options?)` backfills a per-session
    `Map<jsonlPath, {offset, turn_index}>` from storage at boot, watches
    `~/.claude/projects/` recursively via chokidar, dispatches `*.jsonl`
    `add` / `change` events through a serialized processing chain so file
    growth is processed in order.
- `src/daemon/index.ts`: registers the extractor after the FS and git
  watchers, and tears it down before the others on shutdown.
- `tests/capture/extractors/claude-code.test.ts`: 15 tests. Pure-function
  coverage (offset 0, resumption, partial-line, incomplete turn, orphan
  assistant, malformed JSON, tool-mediated turns, missing file, EOF) plus
  integration coverage (live FS event flow, multi-step append, backfill
  from prior storage, stop hygiene).
- `tests/fixtures/claude-code-session.jsonl`: 8-line static fixture with
  realistic Claude Code shape (`{type, sessionId, message: {role, content},
  timestamp, ...}`); content blocks include `text`, `tool_use`, and
  `tool_result` to exercise the parser.

## Decisions made

1. **Source string: `fs:<jsonl_path>`.** Spec offered `claude-code:<session_id>`
   or `fs:<jsonl_path>` and required matching item 010's choice. 010 picked
   `fs:`; 011 follows.

2. **Backfill via exact byte_offset in metadata, not approximate replay.**
   The spec offered an approximate strategy with a 10-second SHA-dedup
   guard. I stored `byte_offset` directly in event metadata and skipped the
   dedup — exact offset → no duplicates by construction. Documented in
   `agent_notes` so the founder can compare to the spec's described
   approach.

3. **Realistic JSON shape, not the spec's literal `role: 'user'` shape.**
   Real Claude Code emits `{type, sessionId, message: {role, content},
   timestamp, ...}` with `content` either a string or an array of typed
   content blocks (`text`, `tool_use`, `tool_result`). The parser walks
   `message.role` and `message.content`; rejects rows where the role isn't
   `user` or `assistant` or where the content has no extractable text.
   Without this, the extractor would emit zero turns against real Claude
   Code data, which is the entire point of the surface.

4. **had_tool_use flag is per-turn, not per-line.** Tool-only lines that
   appear between a user and the next text-bearing assistant flip the flag
   on the emitted turn. `had_tool_use` is omitted from metadata when
   false (kept the metadata clean). The fixture's middle turn
   ("Now with tools" → "Found two files.") exercises this end-to-end.

5. **Optional `options` parameter on `startClaudeCodeExtractor`.** Same
   reasoning as item 010: tests inject a temp `projectsPrefix` so they can
   create JSONL files inside chokidar's watch tree. Production calls
   `startClaudeCodeExtractor(storage)` exactly as documented.

6. **Did NOT modify `src/capture/sources.ts`.** `~/.claude/projects/` is
   already in `fs_paths` from item 009. No allowlist change needed.
