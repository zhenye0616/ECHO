### What I implemented

- **`src/capture/surfaces/git-watcher.ts` (new, ~290 LoC):**
  - `startGitWatcher(repoPaths, storage, options?)` — sets up chokidar watchers
    on `.git/refs/heads/` (recursive) and `.git/HEAD` per repo, plus a
    `setInterval` poll (default 30 000 ms) that runs `git rev-parse HEAD` per
    repo. On head change, `enumerateNewCommits()` runs
    `git log <last_seen>..<head> --reverse --format=...` (or backfill of N
    most recent commits if no last_seen) and emits one CandidateEvent per
    commit through `processCandidate`.
  - Commit fields parsed using a `%H%x1f%P%x1f%aI%x1f%an%x1f%s%x1f%b%x1e`
    custom format — record-separator `0x1E` between commits, unit-separator
    `0x1F` between fields. Safe for multi-line commit bodies.
  - Per-commit `git show --shortstat` for files_changed/additions/deletions.
  - Diff via `git diff <parent>..<sha>` (or `git show` for root commits);
    truncated at 100 KB with `[diff truncated at 102400 bytes; full diff at <sha>]`.
  - Initial backfill kicked off in the background (not awaited) so the
    function returns quickly. `stop()` waits for in-flight refreshes via a
    tracked `Set<Promise<void>>` and `Promise.allSettled`.
  - Per-repo `busy` flag serializes overlapping refresh attempts.

- **`src/capture/sources.ts`:** added `git_repos: ['~/Desktop/Project_echo/']`

### Decisions made (not pre-specified)

1. **Background initial backfill.** `startGitWatcher` returns after FS+poll
   setup; backfill runs in the background. Reason: SIGINT during a 50-commit
   backfill (~3-5 s of git subprocess work) was leaving chokidar handles open
   and timing out the lifecycle SIGINT test at 20 s. The background pattern
   plus a `stopped` cooperative-cancellation flag plus a tracked `inFlight`
   set lets `stop()` resolve cleanly mid-backfill.

2. **Non-spec optional 3rd parameter `options: GitWatcherOptions`.** Adds
   `pollIntervalMs` (default 30 000) and `enableFsWatch` (default true).
   Spec signature `startGitWatcher(repoPaths, storage): Promise<{stop}>`
   remains compatible — production never passes options. Tests use them for
   fast deterministic coverage of polling path vs fs-watch path.

3. **`last_seen_sha` discovery.** Spec says "query for source: 'git:<repo>',
   limit: 1, sort: 'timestamp DESC'" but the `QueryFilter` interface from
   item 008 has no `sort` field. Worked around by querying all events for the
   source and picking the entry with max timestamp. Linear scan, fine for
   per-repo event volumes. Adding `sort` to `QueryFilter` would be a separate
   item — flagged in `agent_notes` for founder.

4. **Daemon ordering: lifecycle first, watcher second.** Originally placed
   the watcher before lifecycle. Two daemon-lifecycle tests broke because
   the watcher's `started` log preceded the lifecycle's, and `waitFor(message
   === 'started')` matched the wrong line. Reordered so lifecycle is up
   before any capture surfaces. Side benefit: PID lock acquired before
   capture begins, which is the safer ordering anyway.
