# Agent Run: 084 Install Profile Split

## What I Implemented

Implemented the customer-default vs dogfood-opt-in install profile split for `echoctl init`.

- Added `--profile customer|dogfood` plus answer-file `profile`, with precedence CLI > answer file > recorded onboarding profile > unconditional `customer`.
- Persisted the resolved profile into `state/onboarding.json` immediately after `ensureEchoHome()`, and emitted the loud restore warning for existing profile-less onboarding state.
- Added skill audience filtering at hop 1: customer installs get customer/untagged skills only, while dogfood installs get all shipped skills.
- Gated roles/workflows in `syncAll()` so customer skips are successful no-ops and dogfood preserves the current full coordination surface.
- Threaded profile through `Wizard.wire()` and `wireAgents()`.
- Added doctor JSON/report-model and text output for the active profile.
- Hardened `tools/foreign-install-smoke.sh` to assert default customer surface, no-flag customer rerun, and explicit `--profile dogfood` full surface.
