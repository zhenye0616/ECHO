# Agent Run: Read-time normalizer — `CaptureEvent` → `NormalizedContextEvent`

## What I Implemented

A new `src/normalize/` module that adapts the storage-shape `CaptureEvent`
into the richer `NormalizedContextEvent` consumer contract at read time.
Storage and the capture pipeline are untouched.

Public API (from `src/normalize/index.ts`):

- `normalizeEvent(event: CaptureEvent): NormalizedContextEvent | null` —
  `null` ⇔ "no adapter matched the event's source." Malformed payload with
  a matching adapter throws `NormalizationError` (carries the source
  `CaptureEvent` on `cause`).
- `normalizeEvents(events: CaptureEvent[])` — drops `null` returns silently.
- `getRegistry()` / `findAdapter(source)` — for tests and for inspection.
- Artifact-identity helpers: `fileArtifact`, `repoArtifact`, `branchArtifact`,
  `commitArtifact`, `conversationArtifact`, `normalizeRemoteUrl`.

Adapters registered in spec order (first-match-wins):

1. `claude-code` — `^fs:.*\/\.claude\/projects\/.*\.jsonl$`
2. `codex`       — `^fs:.*\/\.codex\/sessions\/.*\.jsonl$`
3. `cursor`      — `^fs:.*\/Cursor\/User\/globalStorage\/state\.vscdb$`
4. `git`         — `^git:`

Each adapter is pure: no `Date.now()`, no `fs`, no clock, no I/O.
`time.occurred_at` always sources from `event.timestamp`.

`provenance` is mandatory on every emitted atom: `source_event_id` =
`event.id`; `raw_payload_hash` = sha256(event.content) hex via
`node:crypto`; `extractor_version` = `'<adapter-name>@1'`.

## Decisions Made During Implementation

### Decision 1: Source-pattern regexes

The spec listed regexes with the explicit instruction "verify these by
reading the four extractor source files." I grepped
`src/capture/extractors/*.ts` and `src/capture/surfaces/git-watcher.ts`
for `source: \`fs:` / `source: \`git:`. The shipped strings match the
spec'd patterns 1:1 (claude-code emits `fs:${jsonlPath}`, codex emits
`fs:${jsonlPath}`, cursor emits `fs:${globalDbPath}`, git-watcher emits
`git:${repoPath}`). No spec amendments needed.

### Decision 2: Cursor `deleted_files` mapping

The per-adapter spec note maps cursor's `metadata.context` into "both
`artifacts[]` (the referenced files) and `context.visible[]` (the
attached files)" but is silent on `deleted_files`. I included deleted
files as file artifacts as well — they are observable join keys (just
like referenced files) and the alternative (drop them silently)
reduces signal. Per-adapter test asserts this. Open to redline if the
founder prefers them dropped or surfaced via `state.delta`.

### Decision 3: File artifacts on claude-code / codex turns

The spec says `artifacts: [conversationArtifact('claude_code', session_id)] minimum`.
I add file artifacts when `metadata.files_referenced` is present (CC
populates this from tool calls; codex populates similarly). This is
strictly additive — the conversation artifact is always first — and is
load-bearing for the killer-demo join (Cursor turn referencing `main.ts`
→ Codex turn editing `main.ts` → git commit touching `main.ts` should
all share the same file `id` under the same repo). Same canonical-id
rule (`<repo_id>::<rel_path>`).

### Decision 4: `provider` derivation for repos

`repoArtifact(remote, root)` returns `provider: 'github' | 'gitlab' | 'bitbucket' | 'git'`
based on the host of the normalized URL, or `'local'` when no remote
is present. Helps consumers filter by hosting service without
re-parsing the URL.

### Decision 5: `git_state.origin_url` for claude-code

CC's `metadata.git_state` does not carry `origin_url` today (only
sha + branch + dirty_count). I read `git_state.origin_url` defensively
in case it's added later, but the test fixture intentionally omits it —
so the CC golden test asserts `local:<root>` repo IDs, matching the
shipped data shape.
