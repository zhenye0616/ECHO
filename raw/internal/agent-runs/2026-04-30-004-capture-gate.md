# Run Log — 2026-04-30-004-capture-gate

## What I implemented

`src/capture/gate.ts` (97 lines):

- Pure(-ish) total function `gate(event: unknown): GateResult`. Never
  throws; always returns a `GateResult`.
- Boundary validation: `event` must be a plain object with `source` (non-
  empty string), `timestamp` (non-empty string), `content` (string), and
  optional `metadata` (plain object) — anything else is `malformed_event`.
- Source format `<kind>:<id>` parsed by `indexOf(':')`. The four
  recognized kinds are `app | domain | fs | api`. Unknown kind, missing
  colon, leading colon, or trailing colon → `malformed_event`.
- Dispatch table maps kind → public predicate from
  `src/capture/sources.ts` (`isAllowedApp/Domain/Path/Api`) and to the
  matching `unknown_*` rejection reason.
- Allowlisted → `{ accepted: true, reason: 'allowlisted' }`.
- One log line per call via `createLogger('capture.gate')`:
  - Accept: `info` level, payload `{ source, timestamp }`, message `accepted`.
  - Reject (any reason): `warn` level, payload `{ reason, source? }`,
    message `rejected`.

`tests/capture/gate.test.ts` (224 lines, 28 cases):

- Reject-against-empty-allowlist: each of 4 kinds emits the matching
  `unknown_<kind>` reason and a `warn` log entry with payload assertions.
- Malformed cases (17 total): primitives, missing/wrong-typed fields,
  empty/no-colon/leading-colon/trailing-colon source, unknown kind
  prefix, wrong-typed metadata.
- Accept path via fixture-allowlist mutation in `try`/`finally` (so the
  empty-default state is restored after each test). Covers all four
  kinds, including fs prefix-match.
- Determinism: 100 identical inputs → 100 identical results and 100
  log lines.
- Total-function guarantee: gate doesn't throw for `Symbol`, function,
  `Map`, null-prototype object, nested junk values, or `metadata: null`.
- One-JSON-line-per-call invariant.

## Decisions made during implementation

- **Source kind set is closed.** `kind ∈ {app, domain, fs, api}`
  hardcoded in a literal type and dispatch table. The spec lists those
  four; I rejected the temptation to add a "this is the canonical place
  to extend kinds" comment because the spec also says "Out of Scope:
  fancy error types or exceptions" — adding extension scaffolding would
  be drift.
- **Source string parsed via `indexOf(':')`, not `split(':')`.** Source
  ids may legitimately contain colons (file paths, URLs). The kind is
  the prefix up to the first `:`; the id is everything after. Tested
  via path-style sources with embedded slashes.
- **Empty / leading-colon / trailing-colon all → `malformed_event`.**
  `:foo` and `app:` both have a degenerate side, so neither is a valid
  `<kind>:<id>` pair. The check is `sep <= 0 || sep === source.length - 1`.
- **Fixture allowlist via runtime mutation in tests.** The spec
  explicitly permits "a constructable test allowlist." Rather than add
  a `_gateWith(event, predicates)` internal helper (which would expand
  the export surface beyond what the spec requires), tests mutate
  `CAPTURED_SOURCES.<category>` and clean up in `finally`. The `as const`
  on `CAPTURED_SOURCES` is a type-level assertion; at runtime the
  objects/arrays are mutable.
- **Log message strings are `'accepted'` / `'rejected'`.** Stable so
  the audit page (later) can filter by message in addition to level.
  Payload carries the reason code and source.
- **`metadata` is validated for shape but not propagated to logs.**
  The spec doesn't require logging metadata; doing so would risk
  leaking sensitive payload contents into stdout. Conservative default.
