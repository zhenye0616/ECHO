## Run 2 (resumed at 2026-04-30T22:56Z, agent UUID 78D5AB0F-A8A3-4F01-BC2E-EB05961B2405)

### What I implemented (this attempt)

After the spec was rewritten to Option 1 (watch globalStorage; track
per-composer; workspace_id best-effort), implemented the extractor end-to-end:

- `extractCursorTurns(globalDbPath, lastSeenBubbleIdPerComposer)`: pure async
  function that opens the global state.vscdb read-only via better-sqlite3,
  queries `cursorDiskKV WHERE key LIKE 'bubbleId:%'`, parses each row's key
  as `bubbleId:<composer_id>:<bubble_id>`, parses the JSON value to
  `{role, text, createdAt}`, groups by composer, sorts by createdAt, takes
  bubbles after the per-composer checkpoint, pairs consecutive
  (user, assistant) bubbles. Solo trailing user → not emitted; orphan
  assistant → warn + drop; checkpoint-not-found → warn + skip composer;
  malformed JSON / non-user-or-assistant role → row skipped.
- `startCursorExtractor(storage, options?)`: backfills the lastSeenMap from
  storage (`source: fs:<globalDbPath>`, scans events, takes the latest
  per-composer assistant_bubble_id), starts a chokidar watcher on
  `dirname(globalDbPath)` and `workspacePrefix`, dispatches global-DB events
  to extraction and per-workspace `state.vscdb` events to a
  `Map<composer_id, workspace_hash>` refresh. Each global event runs the
  extractor and pipes turns through `processCandidate(...)`. The processing
  chain is serialized via a single `Promise` chain so workspace events queued
  before global events get to update the map first.
- Each emitted CandidateEvent: `source = fs:<globalDbPath>`,
  `timestamp = new Date(mtime).toISOString()`,
  `content = "USER: <user>\n\nASSISTANT: <assistant>"`,
  `metadata = {composer_id, user_bubble_id, assistant_bubble_id, mtime,
  workspace_id?}` (workspace_id absent when the in-memory map has no entry —
  no null, no empty string, per spec).
- `src/capture/sources.ts`: `CAPTURED_SOURCES.fs_paths` extended with
  `~/Library/Application Support/Cursor/User/globalStorage/`. The existing
  workspaceStorage entry is preserved (item 009 still needs it, and the
  workspace-inference handler reads from it).
- `src/daemon/index.ts`: registers `startCursorExtractor(storage)` after the
  fs and git watchers, and tears it down before the others on shutdown.

### Decisions made during implementation

1. **`startCursorExtractor` signature: optional `options` parameter added.**
   The spec body documents `(storage)`. I added an optional second arg
   `{globalDbPath?, workspacePrefix?}` with the production defaults pointing
   to `~/Library/Application Support/Cursor/User/...`. Production calls
   match the documented signature exactly (`startCursorExtractor(storage)`
   in `src/daemon/index.ts`); tests inject tempdir paths via the optional
   arg. Without it, the watcher would have no testable path-injection point
   short of monkey-patching `os.homedir()`. Non-breaking extension.

2. **Watching `dirname(globalDbPath)` rather than the file itself.**
   chokidar's behavior on a non-existent file path varies; watching the
   parent directory and dispatching by exact-match path is more reliable
   and lets the watcher pick up the file's first creation. The allowlist
   entry is the directory anyway.

3. **`tests/capture/sources.test.ts` updated outside `files_to_modify`.**
   The "Allowlist update" acceptance criterion mandates extending
   `fs_paths`; the existing test asserts the array exhaustively
   (`toEqual([workspace, claude])`), so this test must update to
   `toEqual([workspace, global, claude])` for the build to remain green.
   This is a deterministic side-effect of the acceptance criterion, not
   a scope expansion. Flagged here in case the founder wants it reverted
   and the test re-shaped in a separate item — the change is one line.

4. **Bubble JSON shape assumed: `{role, text, createdAt}`.**
   This matches the spec's parsing description literally. The drift note
   from Run 1 deliberately did not probe bubble values to keep founder data
   out of the agent transcript, so the actual field names in real Cursor
   are not verified here. If lag verification (acceptance criterion below)
   fails because the real shape is different (e.g., `{type, text}` with
   numeric type code), the parser needs a small adjustment in a follow-up.
   The strict-shape failure mode is a `null`-return per row + log debug —
   the daemon stays alive and emits zero events for that DB.

5. **Orphan-and-checkpoint defenses.**
   - Orphan assistant (no preceding user) → `log.warn` and drop, continue.
   - Checkpoint bubble_id not found in current DB rows → `log.warn` and skip
     this composer for this round (do NOT re-emit from start, which would
     create duplicates if the bubble was just evicted from a paged-out
     window).

6. **Initial workspace-inference scan: NOT done.**
   Spec says "On any FS event for a per-workspace `state.vscdb`,
   ... update the map." A boot-time scan would widen this. Consequence:
   on a fresh ECHO daemon boot before any per-workspace `state.vscdb` has
   been touched by Cursor, the first turn for a known composer ships
   without `workspace_id`. The next Cursor write to any workspace DB
   triggers a refresh. Per spec, `workspace_id` is best-effort by design.
   Flagging here in case the founder wants a boot scan added later.
