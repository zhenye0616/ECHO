1. **Eight product tests are byte-parity leaves, not executed.** They reference item-132
   qualification tooling and CI files via runtime `join(REPO_ROOT, '<literal>')` construction
   passed to `spawnSanitizedChild`/`readFileSync`. Those are computed-base runtime paths, not
   module edges, so the fixed-point resolver records them as parity-only references and does
   not follow them. Executed suite = `tests/migration/**` + `tests/product/end-to-end-synthetic.test.ts`.
2. **AC3↔AC5 schema-path tension (surfaced, not hidden).** The byte-identical
   `src/product/config.ts:55` loads its schema at runtime from
   `../../schemas/product/runtime-config.v1.schema.json`, and the byte-identical `package.json`
   `files` field references that same `schemas/product/...` path — but AC5 names the committed
   schema `schemas/runtime-config.v1.schema.json`. Because production TS and package.json are
   byte-immutable, the only build-coherent reconciliation is: commit the schema at the AC5 path
   (`schemas/runtime-config.v1.schema.json`) and have `verify-artifact.mjs` stage it into the
   tarball at `schemas/product/runtime-config.v1.schema.json` so the unchangeable runtime loader
   resolves it. This is what was built. **A reviewer should confirm this reconciliation or
   direct the alternative (schema copied same-path at `schemas/product/...`).**
3. **Dev/test toolchain is provisioned out-of-band**, not a runtime dependency: the
   byte-identical `npm-shrinkwrap.json` is runtime-only (ajv, better-sqlite3; 44 packages, zero
