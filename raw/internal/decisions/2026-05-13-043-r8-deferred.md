# 043 R8 HIGH #1 deferred — TOOL_DIR/TARGET_REPO split in shell helpers

**Date:** 2026-05-13 ~08:50 UTC (043 merge time)
**Context:** Drift-event note per CLAUDE.md "Drift Prevention" — recording a deferred spec requirement so the next item that fires AC6h-style fixture-local tests can find it.

## What was specced

Per `backlog/complete/2026-05-13-043-per-round-reviewer-roster.md` AC3 + AC6h, spec R8 HIGH #1 (added in r8 disposition) mandated:

> Split `TOOL_DIR=$(cd "$(dirname "$0")" && pwd)` from `TARGET_REPO="${ECHO_REVIEW_QUEUE_REPO_ROOT:-$(git -C "$(dirname "$0")" rev-parse --show-toplevel)}"` in `tools/review-queue/commit-reviewer-response.sh` and `tools/review-queue/push-with-retry.sh`. All `git` invocations use `git -C "$TARGET_REPO"`; all file writes use `$TARGET_REPO/...`; all tool invocations use `$TOOL_DIR/...`.

The purpose: make the shell pipeline honor `ECHO_REVIEW_QUEUE_REPO_ROOT` end-to-end so AC6h's fixture-local "REAL pipeline" test can run without copying the tool tree.

## What landed in 043

The builder agent did NOT implement this split. Both files still derive `REPO_ROOT` via bare `git rev-parse --show-toplevel` (cwd-based) and use bare `git add`/`git commit`/`git push` invocations.

## Why deferring is safe (at this merge)

Production reviewer ticks (launchd Codex job, `run-codex-reviewer.sh` → `_run_reviewer.sh` → reviewer prompt → `commit-reviewer-response.sh`) work correctly because:

1. The wrapper `cd`s into `ECHO_REVIEW_QUEUE_REPO_ROOT` first (per 041 AC1).
2. The reviewer prompt body runs in that cwd.
3. `commit-reviewer-response.sh` derives `REPO_ROOT` via `git rev-parse --show-toplevel` — which returns the right repo because cwd is correct.

The only case where the split matters is when:
- A test/fixture sets `ECHO_REVIEW_QUEUE_REPO_ROOT=$FIXTURE/repo` BUT invokes the helpers from a DIFFERENT cwd (e.g., the production repo's tool tree).
- In that case, the bare `git rev-parse` returns the cwd's repo (production), not the fixture.

This is exactly the AC6h test scenario, which 043 also did NOT implement. So the missing implementation and the missing test are coupled — they only matter together.

## Where this surfaces next

The 044 follow-up item — currently slugged `2026-05-XX-044-add-3rd-reviewer-end-to-end-falsification` in `_followups.md` — will need to land BOTH:

1. The TOOL_DIR/TARGET_REPO split (~20 lines of shell across the two helpers).

Together they close the "adding a 3rd reviewer works end-to-end" promise that R2 HIGH #1 introduced and 043 partially delivered.

## What did NOT change in 043 production behavior

- Reviewer launchd ticks: identical to pre-043 (because cwd routing already worked).
- Smoke tests (`tools/review-queue/smoke-test-codex-runner.sh`): still pass because the smoke test sets cwd correctly via `ECHO_REVIEW_QUEUE_REPO_ROOT` + the wrapper's `cd`.
- The Python pipeline (`request.py`, `combine.py`, `_reviewers.py`, `validate.py`) DOES honor `ECHO_REVIEW_QUEUE_REPO_ROOT` per 043 AC2 — only the shell helpers don't.

## Decision rationale

Strategist + founder agreed at 043 merge time: ship the framework (AC1, AC2, AC3, AC4, AC5, AC6, AC7) without the TOOL_DIR/TARGET_REPO split since it only matters for a missing test that's also deferred. Filing 044 bundles both pieces of the AC6h promise into one builder cycle.

The alternative (push 043 back to `claimed/` for the builder to add ~20 lines of shell + the missing test) was rejected as a worse cost-benefit trade — the test surface is the harder part, the shell split is mechanical.
