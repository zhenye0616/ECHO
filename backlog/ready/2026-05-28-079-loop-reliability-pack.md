# 079 — Loop Reliability Pack

## Why (the friction this closes)

The multi-agent loop (atomic claim → ephemeral-worktree build → cross-vendor review rounds → watcher disposition → merge-and-cleanup) is the dogfooding infrastructure for the V1 wedge. It works — but Codex's loop-inefficiency analysis surfaced four recurring RELIABILITY frictions that cost founder-interventions and wasted review rounds:

1. **Automation reads/writes the founder's live checkout.** The 050 worktree-isolation invariant says automated runners must never share the founder's live `.git/index` — but the clean-snapshot preamble is COPY-PASTED across `_run_reviewer.sh`, `review-queue-watch.md`, and `merge-and-cleanup.md`, and `combine.py --all` can still commit into the live checkout. Dirty-tree and local-behind friction recur because clean-snapshot is a convention, not the enforced default.
2. **Tests can launch production effects.** Each side-effectful runner (spawn agent / `codex exec` / `git push` / launchd / review tick) reinvents its own stub seam. 077→078 surfaced cases where a test path could fire a real vendor CLI or a real push. The fix is one shared effect boundary with `live | dry-run | test` modes — generalizing beyond `_run_reviewer.sh`'s ad-hoc `command -v` guard.
3. **Review-handoff artifact is synthesized by hand.** The code-reviewer subagent, `/review-pending`, and the codex children all emit "the same review" — but the contract is implicit (the orchestrator greps for the right headings; `merge-and-cleanup` re-scrapes `verdict:`/`reviewed_at:` with awk). Manual sidecar synthesis is where producer/consumer drift hides.
4. **Coupled files drift because the check is prose, not mechanism.** `package.json ↔ package-lock.json` lockfile-miss recurred 077→078; skill-adapter sync, MCP-registration coherence, and manifests are all checklist-driven at `merge-and-cleanup` C5. A mechanical pre-merge invariant checker turns "the human remembered to run it" into a gate.

This is **operating-model reliability hardening** — NOT a new product surface, NOT a new orchestration layer (Codex was explicit). It removes friction from the loop that already exists; it adds no new role, no new coord event, no new MCP tool, no new daemon code.

## Locked scope (what 079 IS)

- **Preserve, do not touch:** atomic claim, reviewer independence, ephemeral worktrees (079 makes them the *default*, not a new mechanism), cross-vendor review, founder-gate-only-at-judgment (substantive-conflict + push-to-main).
- **AC1-AC4 are the load-bearing core** (one per Codex fix 1-4). **AC5 is stretch** (Codex fix 5 — executable patch-drift classification). **Codex fixes 6-7 are deferred siblings** (After-Completion).
- Refactor-to-shared and gate-don't-auto-fix throughout: every change is byte-identical under `live`/production to today's behavior; the new value is enforcement + de-duplication + a validated contract.

## Acceptance Criteria

1. **AC1 — clean snapshots as the default execution substrate.** A shared `tools/review-queue/_clean-snapshot.sh` exposes `echo_enter_clean_snapshot <role-slug>` that performs the 050 preamble (prune → enumerate registered → GC >60min orphans → `git fetch origin main` → require `TMPDIR` → `git worktree add --detach $TMPDIR/echo-<role>-<uuid> origin/main` → export `$WT` + set `ECHO_REVIEW_QUEUE_REPO_ROOT=$WT` → install unified ERR/EXIT cleanup trap). `_run_reviewer.sh` (and, in prose, the watcher + merger skills) source it instead of holding their own copy; the resulting worktree setup is **byte-identical** to the three pre-refactor inline copies (test-asserted). `combine.py`'s git-mutating path **refuses to run against the founder's live checkout** unless inside an `echo-<role>-<uuid>` snapshot OR `--allow-live` is passed, with a clear diagnostic. The founder's live checkout is an operator workspace, never shared automation state. Crash-safe + idempotent (re-fireable; trap discards on any exit).

2. **AC2 — one effect boundary for every side-effectful runner.** A shared `tools/review-queue/_effect-runner.sh` exposes `echo_effect <kind> -- <argv...>` for `kind ∈ {spawn-agent, codex-exec, push, launchd, review-tick}`, reading `ECHO_EFFECT_MODE ∈ {live, dry-run, test}` (default `live`). `live` execs argv unchanged (production byte-identical); `dry-run` prints + returns 0 without executing; `test` no-ops to a per-kind canned success. `push-with-retry.sh`'s push and `_run_reviewer.sh`'s child-CLI dispatch route through it. Under `ECHO_EFFECT_MODE=test`, a reviewer-wrapper smoke launches **no real vendor CLI** and a push performs **no real git push** (test-asserted). The 050 refspec, retry, and queue-errors fallback in push-with-retry are all preserved.

3. **AC3 — unify the review-handoff artifact.** A canonical `tools/review-queue/schemas/review-sidecar.schema.json` + `tools/review-queue/validate-sidecar.py` pin the `<id>.review.md` contract (frontmatter `item_id`/`verdict`/`reviewed_at`/`test_counts` + additive `producer` field + the 8 required `## <heading>` sections that `/review-pending` and the code-reviewer subagent already emit). `/review-pending` Step C stamps `producer`, validates via `validate-sidecar.py` before commit+push (fail-loud on invalid). `/merge-and-cleanup` Step A **consumes the validated artifact** (`validate-sidecar.py` then read `verdict`/`reviewed_at`) instead of ad-hoc `awk` scrapes — regardless of which producer wrote it. Both canonical skills re-synced via `tools/sync-skills.sh`. No producer-specific synthesis path remains.

4. **AC4 — pre-merge invariant checker for coupled files.** A mechanical `tools/review-queue/check-coupled-invariants.sh` (run from the merger worktree) asserts: (i) `package.json ↔ package-lock.json` coherence (catches the 077→078 lockfile-miss); (ii) skill-adapter sync (invokes `tools/sync-skills.sh --check`); (iii) MCP-tool registration coherence (every `registerX` in `src/mcp/server.ts` has a matching tool file + the registration test recognizes it). Exits non-zero with a per-invariant diagnostic naming the drifted pair. `/merge-and-cleanup` Step C5 runs it alongside `npm test`/`lint`/`typecheck`/`sync-skills --check` and **pauses-don't-auto-fix** on failure. Mechanical at the gate, not checklist-prose.

5. **AC5 (STRETCH) — make review-round patch-drift executable.** A `tools/review-queue/classify-finding-provenance.py` reads a just-combined `combined.md` + the item's prior-round `spec-r*-patches` git diffs and classifies each actionable finding as `original_contract | prior_patch_introduced | propagation_gap` (the exact broad-lookback signal `review-queue-watch.md`'s reframe gate already describes in prose). It emits a machine-readable provenance count so the loop can surface "the review is creating bugs in its own patches" before round-count alone. Read-only over git + combined.md; zero side effects. **It only PRODUCES the classification — wiring it into the watcher's reframe gate is a separate follow-on, OUT of scope here.** Ships only if AC1-AC4 land with budget remaining; otherwise the whole file defers to the After-Completion sibling list.

6. **AC6 — observational reliability gate (merged → validated, NOT a dogfooding-marker gate).** Because 079 adds no MCP tool / no surface, its validation is the **next full review→merge cycle after merge** running through the new substrate with **zero founder-intervention** on the four friction classes: no dirty-tree refusal at merge-and-cleanup pre-flight caused by automation writing the live checkout, no local-behind surprise, no manual sidecar field synthesis, no post-merge lockfile/adapter/registration drift that the gate should have caught. Founder records a one-line note on whether the loop felt more reliable. (This is the empirical close, not a new metric.)

7. **AC7 — tests + checks green.** Per-AC shell tests (`test-clean-snapshot.sh`, `test-effect-runner.sh`, `test-validate-sidecar.sh`, `test-check-coupled-invariants.sh`, and `test-classify-finding-provenance.sh` iff AC5 ships) all pass; `tools/sync-skills.sh --check` clean after the two canonical-skill edits; root `npm test`/`lint`/`typecheck` green (the daemon suite is only touched by AC4's read-only registration check, which adds no production TS). ## Design judgment calls (flagged for r1 reviewer pushback)

- **J1 — combine.py live-checkout guard shape.** AC1 makes `combine.py`'s git-mutating path refuse on the live checkout unless `--allow-live`. Alternative: have `combine.py` auto-enter its own clean snapshot (like the runners). Default chosen: **guard-with-opt-out**, because the watcher already routes combine through `$WT` (so the steady-state path is unaffected) and the only live-checkout caller is the ad-hoc `combine.py --all` batch the operator runs deliberately. Auto-entering a snapshot from a Python script would duplicate the bash worktree logic in a second language. Reviewers: is the guard sufficient, or does an operator footgun remain that justifies auto-snapshot?

- **J2 — scope of AC4 invariants (i) and (iii).** (i) lockfile coherence: is `npm ci --ignore-scripts --dry-run` the right non-network check, or is a `lockfileVersion`+top-level-deps compare cheaper/more reliable on the founder's machine? (iii) MCP-registration coherence: how deep — just "every `registerX` has a tool file", or also "the registration/audit-contract test enumerates it" (the exact 078 drift)? Default: keep (iii) to the structural check (register↔file + test-recognizes), NOT a full daemon boot. Reviewers: pressure-test whether (iii) can be made mechanical without re-running the whole daemon suite.

- **J3 — effect-runner `kind` taxonomy.** AC2 fixes `kind ∈ {spawn-agent, codex-exec, push, launchd, review-tick}`. Is `codex-exec` too vendor-named (should it be `agent-exec` to stay 056-vendor-agnostic)? Are five kinds the right cut, or should `review-tick` collapse into `spawn-agent`? Default: five kinds, `codex-exec` relabeled `agent-exec` if reviewers agree the vendor-neutral name is clearer. The behavior (live/dry-run/test) is identical across kinds; the label is only for the dry-run diagnostic + per-kind canned test success.

- **J4 — AC5 stretch boundary.** AC5 produces a classification but does NOT wire it into the watcher. Is producing-without-wiring genuinely useful in this item, or is an unwired classifier dead weight until the follow-on lands? Default: ship the classifier + its test as a self-contained, separately-verifiable unit (so the follow-on is pure wiring), but ONLY if AC1-AC4 land first. Reviewers may argue to defer AC5 whole.
