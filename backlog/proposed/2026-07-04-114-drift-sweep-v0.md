## Problem

Nothing detects understanding-drift: a newly captured statement contradicting a recorded team decision goes unnoticed unless a human happens to see both. Absence has no event — no push mechanism can catch it — so this must be a clocked sweep. v0 per the loop-scope decision: one company-level drift class, statement supply = Granola signals only, alert = Slack message to the decision owner. This is the YC demo hero scene.

## Acceptance Criteria

- **AC1 — clocked worker with durable arrival-order cursor:** a sweep worker registered in `startEnrichmentDispatch` (interval + single-flight + `runSignalsFirst`-style chaining after the signal worker, per the intake-bridge template). Progress cursor = append-order `sequence_id` watermark persisted via atomic write; each tick reads `getSignalWindow({cursor, scope: 'company'})`. The watermark advances only after every eligible statement in the tick's window has reached a terminal per-pair state (judged-and-delivered, no-match-skipped, terminal-judge-failed, or delivery-failed-and-recorded per AC3/AC5); a partial tick failure must not advance the cursor past unprocessed or mid-flight arrivals. Test: a late-ingested statement (old timestamp, post-watermark arrival) is swept exactly once; a tick that crashes after judging but before the watermark write re-processes the same window next tick without skipping arrivals or double-delivering.
- **AC2 — the join:** new `derived:granola-signals` statements (types `decision`/`rationale`/`action`) are joined against `queryLatestTeamDecisions()` by exact `canonical_subject` equality (112's key). No-match statements are skipped silently. Test: same-subject pair joins; different-subject pair does not.
- **AC3 — idempotent brain judge:** each (decision `dedupe_key`, statement `dedupe_key`, judge version) pair is judged at most once ever (checkpoint file, `granola-signals` checkpoint pattern), via a strict-JSON `runBrain` verdict prompt (`{contradicts: boolean, quote: string, reason: string}`). The pair's checkpoint is written atomically as the last step of judging, before AC5 delivery; a crash before that write leaves the pair unjudged and it is re-judged next tick (re-judging is harmless — only delivery is guarded, per AC5). Distinguish two failure classes: **(a) terminal** — a malformed/parse verdict after bounded retries is recorded as failed for that pair, never re-judged at the same judge version, never alerts; **(b) retryable** — a `runBrain` infrastructure error (network/model outage) is NOT terminal, left unjudged for a later tick, so a transient outage cannot become permanent silent suppression. Terminal judge failures emit durable operator-visible evidence (pair keys, judge version, failure reason, per-tick counts, via the existing structured queue-error/health channel) so a model regression that malforms every verdict surfaces instead of silently suppressing all contradictions. Tests: re-running the sweep over the same window produces zero new brain invocations; a stubbed infra error is retried (not terminal) while a stubbed malformed verdict is terminal and emits a visible failure count.
- **AC4 — code-enforced faithfulness:** the verdict's `quote` must appear verbatim in the statement atom's content; otherwise the verdict is discarded and logged (`drift_verdict_rejected`). This is a code check, not a prompt instruction. Test with a fabricated-quote judge stub.
- **AC5 — alert to the owner, confirm-card contained:** on a surviving `contradicts: true`, post a Slack card to the decision's owner-of-record (`confirmed_by`, resolved via a new reverse `cofounderIdToSlackUserId` helper over the existing identities config) carrying: decision text + its confirmed_at/by, the contradicting quote, meeting title/URL provenance, and Acknowledge/Dismiss buttons. The button callbacks are handled in `src/surfaces/ceo-slack-responder/responder.ts` (new `block_actions` `action_id` branch alongside the existing `echo_decision_*`/`echo_intake_*` handlers); dismissals append to the event log (`ceo-loop-events.md`) as noise signals (existing dismissal-record pattern). Card delivery uses the daemon-side post path (`postGranolaIntakeSeed` pattern) — no Socket Mode dependency. Delivery is guarded by a per-pair delivery state in the AC3 checkpoint (decision `dedupe_key` + statement `dedupe_key` + judge version): an already-delivered pair is never re-posted. Posture is **at-most-once** — record delivery intent before the post and the outcome after; an ambiguous crash around the post boundary is recorded as delivery-failed (operator-visible via AC3's failure channel) and NOT re-posted, so the owner is never spammed and a contradiction is never silently dropped. Tests: a stubbed post failure surfaces as delivery-failed and does not mark the pair delivered; a re-run over an already-delivered pair posts zero new cards.
- **AC6 — fail-closed + blast-radius cap:** disabled by default behind `ECHO_DRIFT_SWEEP_ENABLED`; enabled-but-misconfigured (missing Slack token / unresolvable owner map) → disabled handle with a structured config error, never a daemon crash. Max alerts per tick capped (default 3); overflow logged, not posted. Tests for both.

## Out of Scope (Don't Drift)

- **No silence/absence digest** ("decisions with no activity") — post-freeze stretch with its own decision record.
- **No Slack or eng-session statement supply** — Granola signals only; Slack capture is a separate gap-map track.
- **No execution-drift** (commits/Linear state vs decisions) — needs Linear read; explicitly later.
- **No alias or semantic subject matching** — exact key only; misses are data for the alias decision, not scope for this item.
- **No decision-store schema changes** and no writes to `derived:team-decisions`.
- A drift *verdict* is never persisted as a fact atom — it exists only in the checkpoint and the Slack card (seam decision 3/6).
