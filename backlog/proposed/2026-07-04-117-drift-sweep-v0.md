## Problem

Nothing detects understanding-drift: a newly captured statement contradicting a recorded team decision goes unnoticed unless a human happens to see both. Absence has no event — no push mechanism can catch it — so this must be a clocked sweep. v0 per the loop-scope decision: one company-level drift class, statement supply = Granola signals only, alert = Slack message to the decision owner. This is the YC demo hero scene.

## Acceptance Criteria

- **AC1 — clocked worker with durable arrival-order cursor:** a sweep worker registered in `startEnrichmentDispatch` (interval + single-flight + `runSignalsFirst`-style chaining after the signal worker, per the intake-bridge template). Progress cursor = append-order `sequence_id` watermark persisted via atomic write; each tick reads `getSignalWindow({cursor, scope: 'company'})`. Test: a late-ingested statement (old timestamp, post-watermark arrival) is swept exactly once.
- **AC2 — the join:** new `derived:granola-signals` statements (types `decision`/`rationale`/`action`) are joined against `queryLatestTeamDecisions()` by exact `canonical_subject` equality (115's key). No-match statements are skipped silently. Test: same-subject pair joins; different-subject pair does not.
- **AC3 — idempotent brain judge:** each (decision `dedupe_key`, statement `dedupe_key`, judge version) pair is judged at most once ever (checkpoint file, `granola-signals` checkpoint pattern), via a strict-JSON `runBrain` verdict prompt (`{contradicts: boolean, quote: string, reason: string}`). Parse failure after bounded retries → recorded as failed for that pair, never re-judged at same version, never alerts. Test: re-running the sweep over the same window produces zero new brain invocations.
- **AC4 — code-enforced faithfulness:** the verdict's `quote` must appear verbatim in the statement atom's content; otherwise the verdict is discarded and logged (`drift_verdict_rejected`). This is a code check, not a prompt instruction. Test with a fabricated-quote judge stub.
- **AC5 — alert to the owner, confirm-card contained:** on a surviving `contradicts: true`, post a Slack card to the decision's owner-of-record (`confirmed_by`, resolved via a new reverse `cofounderIdToSlackUserId` helper over the existing identities config) carrying: decision text + its confirmed_at/by, the contradicting quote, meeting title/URL provenance, and Acknowledge/Dismiss buttons. Dismissals are appended to the event log as noise signals (existing dismissal-record pattern). Card delivery uses the daemon-side post path (`postGranolaIntakeSeed` pattern) — no Socket Mode dependency.
- **AC6 — fail-closed + blast-radius cap:** disabled by default behind `ECHO_DRIFT_SWEEP_ENABLED`; enabled-but-misconfigured (missing Slack token / unresolvable owner map) → disabled handle with a structured config error, never a daemon crash. Max alerts per tick capped (default 3); overflow logged, not posted. Tests for both.

## Out of Scope (Don't Drift)

- **No silence/absence digest** ("decisions with no activity") — post-freeze stretch with its own decision record.
- **No Slack or eng-session statement supply** — Granola signals only; Slack capture is a separate gap-map track.
- **No execution-drift** (commits/Linear state vs decisions) — needs Linear read; explicitly later.
- **No alias or semantic subject matching** — exact key only; misses are data for the alias decision, not scope for this item.
- **No decision-store schema changes** and no writes to `derived:team-decisions`.
- A drift *verdict* is never persisted as a fact atom — it exists only in the checkpoint and the Slack card (seam decision 3/6).
