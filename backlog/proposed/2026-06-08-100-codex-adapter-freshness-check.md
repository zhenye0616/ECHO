## Why

The codex consult on item 099 surfaced a **HIGH** layering finding: the Codex render target — `tools/install-echo-codex-skills.sh` rendering canonical `skills/*.md` into `~/.codex/skills/ECHO:<name>/SKILL.md` — has **no freshness check**. `tools/sync-skills.sh --check` (wired into `check-coupled-invariants.sh`) covers only the Claude adapters (`.claude/commands/` + `~/.claude/commands/`). That blind spot is exactly how a stale Codex `producer` template went undetected for ~11 days (the 087 root that 099 fixes on the writer side).

But the obvious fix — wiring `install-echo-codex-skills.sh --check` into `check-coupled-invariants.sh` alongside the Claude check — is **wrong**, and that's the whole reason B was split out of 099: `~/.codex/skills/` is **HOME-relative operator-local install cache**, not a repo-tracked artifact. Gating *merges* on it would make merges depend on one operator's machine state — a different operator (or CI, or a fresh checkout) with no Codex install, or a stale one, would fail the merge gate for reasons unrelated to the change under review. The Claude adapters can live in the merge gate because `.claude/commands/` is in-repo and the `~/.claude/commands/` copy is dir-existence-guarded; the Codex install is neither.

**Correct placement: operator-side selftest.** The freshness check belongs where operator-local state is legitimately inspected — `echoctl doctor` — backed by an `install-echo-codex-skills.sh --check` mode. doctor already models exactly this: non-fatal `degraded` sub-checks (`syncLock.present`, unprobed agents) that report operator-environment problems without claiming the system is broken. A stale Codex adapter is precisely that shape.

## Locked decisions

1. **Operator-side, never the merge gate** (099 codex consult HIGH). The check lives in `echoctl doctor` + the installer's own `--check`. `check-coupled-invariants.sh` and every CI/merge path stay untouched and HOME-independent. This boundary is the point of the item, not an implementation detail (AC4 guards it).
2. **Discovery by sentinel, namespace-agnostic.** `--check` scans `~/.codex/skills/*/.echo-managed` for `managed_by=tools/install-echo-codex-skills.sh` and re-renders each dir using the sentinel's recorded `source` **and** `skill_name`. Because the installer embeds `skill_name` into the rendered `SKILL.md` (`render_skill` writes `name: <skill_name>`), re-rendering with the recorded `skill_name` reproduces the exact installed content regardless of `--namespace`/`--underscore-names` — so a non-default install is checked correctly without reconstructing the original flags, and without any new sentinel field (both `source` and `skill_name` already exist in `.echo-managed`).
3. **Absent install is a clean pass.** No `~/.codex/skills/`, or zero managed dirs → exit 0 with "nothing to check". A fresh machine, CI, or a non-Codex operator must never fail this check (mirrors `sync-skills.sh`'s `[ -d "$GLOBAL_DIR" ]` guard).
4. **doctor reports, the installer fixes.** On drift, doctor names the stale skill(s) and points the operator at `tools/install-echo-codex-skills.sh` (re-running the installer IS the fix). No auto-repair in this item; drift is `degraded`, not `broken`.

## Acceptance criteria

- **AC1 — `install-echo-codex-skills.sh --check`.** Discovers managed Codex skill dirs via the `.echo-managed` sentinel; for each, re-renders the skill — reading **both** the recorded `source` path **and** the recorded `skill_name` from the sentinel and invoking `render_skill "$source" "$skill_name"`, so the expected content reproduces byte-identically for any install including non-default `--namespace`/`--underscore-names` ones (no new sentinel fields; both already exist) — into a **per-run** temp stage (`mktemp -d` under `${TMPDIR:-/tmp}`, removed by a cleanup trap on every exit path, located strictly outside `~/.codex`), then compares the **actual installed `SKILL.md`'s content_sha** against the freshly-rendered expected content_sha. This single comparison catches **both** source drift (canonical `skills/*.md` changed since install) **and** a hand-mutated installed file (AC5's case); the sentinel's stored `synced_content_sha256` is used only as metadata to classify the drift as source-side vs install-side, never as the sole pass/fail signal. Also flags a managed dir whose `SKILL.md` is missing or whose recorded `source` no longer exists. (A *missing* `.echo-managed` sentinel is out of scope — such a dir is not discoverable as managed, and per AC2 an unmanaged dir is correctly not checked.) The recorded `source` is resolved **cwd-independently**: the installer records it as an absolute path (`$SKILLS_DIR/*.md`, where `SKILLS_DIR` derives from the script's own `pwd`-based `REPO_ROOT` — verified against the live sentinel, which records `source=/…/skills/<name>.md`), used as-is; any non-absolute `source` is resolved against that same installer/`REPO_ROOT` anchor, **never** against the caller's cwd — so an unattended doctor run from any directory never false-reports `source` missing. Prints one line per drifted/missing skill that carries the skill name, a short reason, **and that skill's precise, cwd-safe remediation** — the **absolute** installer path (from the script's own `pwd`-based `REPO_ROOT`) plus that skill's family flags (`--namespace <ns>` / `--underscore-names`, derived from its own sentinel `skill_name`: namespace = the prefix before `:`, underscore-style = the visible name being the canonical basename with `-`→`_`). Because `--check` already holds both its absolute path and each drifted skill's family at detection time, every drift line is independently runnable from any cwd, and a `~/.codex` containing **mixed install families** (default `ECHO:` + a custom `--namespace`) yields one correct command per drifted family with no caller-side reconstruction. **Exit-code contract** (so doctor can distinguish outcomes from the exit code alone, no stdout parsing): **`0`** = ok (every managed skill matches, **or** no managed install / nothing to check per AC2); **`1`** = drift (≥1 drifted/missing skill, or a missing `source`); **`2`** = check/runtime error — the check itself could not complete (e.g. `mktemp` failure, unreadable temp stage, `render_skill` crash, shell abort). Real drift (`1`) and an internal failure (`2`) are **never** conflated, so a broken check is never reported as adapter drift. The check is read-only — it never writes into `~/.codex`.
- **AC2 — absent-install guard.** When `~/.codex/skills/` does not exist, or exists but contains zero `managed_by=tools/install-echo-codex-skills.sh` dirs, `--check` prints `no managed Codex ECHO install; nothing to check` and exits 0 — no HOME write, no failure. Verified from a disposable temp `$HOME`.
- **AC3 — doctor integration.** `echoctl doctor` resolves `tools/install-echo-codex-skills.sh` by an **absolute path from a stable anchor** (the repo root / module location — never cwd or a `PATH` lookup) and invokes it `--check` **`execFile`-style** (no shell-string, no `PATH` resolution) **with a normalized safe `PATH` in the subprocess environment** — because an unattended/launchd/packaged doctor run inherits a sparse environment, doctor sets a known-good `PATH` (covering the shebang interpreter and the script's own dependencies: `mktemp`, `shasum`, `git`, `python3`, `awk`) so neither the interpreter nor the script's internal commands false-degrade or `check-error` under a minimal `PATH`; combined with the absolute path, an arbitrary cwd never degrades on script-not-found. It adds a structured `codexAdapter` field to `DoctorReport` with shape `{ status: 'ok' | 'drifted' | 'check-error'; detail?: string; remediationCommand?: string }`. `status` is derived **purely from the subprocess exit code (AC1's reserved codes) — never by parsing free-form stdout**: **exit `0` → `ok`** (covers both "all managed skills fresh" and "no managed install / nothing to check"; `detail` carries the human line that distinguishes them, so doctor needs no machine discriminator); **exit `1` → `drifted`**; **exit `2`, or a spawn/exec failure (script absent, interpreter missing) → `check-error`**. `detail` carries opaque text the operator reads, sourced by status: for `ok`/`drifted`, the subprocess's captured **stdout** (the per-skill drift lines or the "nothing to check" line); for `check-error`, the captured **stderr** (or the exec/spawn exception message) so an unattended operator always sees *why* the check could not run — `check-error` **never** yields an empty `detail`. In all cases `detail` is opaque: doctor does **not** parse it into structured per-skill data (no `--check` output grammar, no `--check --json`), and `drifted` vs `check-error` classification is driven **only** by the exit code, never by stdout/stderr contents. Mapping (reusing doctor's existing non-fatal vocabulary, exactly like `syncLock.present`): `drifted` → `overall: 'degraded'` with `detail` surfacing the stale skill(s) **and their per-skill remediation lines** (produced by `--check` per AC1 — absolute path + each family's flags), and `remediationCommand` set to a single **cwd-safe absolute** path to the installer (`<abs>/tools/install-echo-codex-skills.sh`) as a generic entry point. doctor does **not** derive flags or construct per-family commands — the precise, per-skill, per-family remediation is `--check`'s own output in `detail`, where it has perfect information at detection time (its own absolute path + each drifted skill's family). This keeps doctor a pure exit-code→status + opaque-passthrough consumer and naturally handles **mixed managed install families**: each drifted skill's own line carries its own correct command, with no doctor-side grouping, flag-derivation, or stdout parsing. `check-error` (installer genuinely missing/unrunnable, shell error) → also `degraded` — **graceful, never `broken`, never throws**; `ok` → no contribution to `overall` (a human ok/skip line). `echoctl doctor --json` includes the `codexAdapter` field; `computeOverall` treats `codexAdapter.status` like the existing non-fatal degrade checks.
- **AC4 — merge gate untouched (the guard AC).** `tools/review-queue/check-coupled-invariants.sh` is not modified and gains no `~/.codex` dependency; no CI/merge path references the Codex install. A grep/assertion that `check-coupled-invariants.sh` contains no `.codex` reference is sufficient.
- **AC5 — tests.** `--check` is exercised in a **disposable temp `$HOME`/`~/.codex`** with a cleanup trap, never touching the operator's real `~/.codex`: clean install → exit 0; a hand-mutated installed `SKILL.md` → exit non-zero naming the skill; **a non-default `--namespace`/`--underscore-names` install with no drift → exit 0** (proves the sentinel-`skill_name` re-render reproduces byte-identically — no false drift on non-default installs); absent dir → exit 0; **the temp stage is removed on every exit path and nothing outside the temp stage is written (`~/.codex` is read-only)**. A doctor test asserts `overall: 'degraded'` with the stale skill surfaced in `codexAdapter.detail` when the check fails, and `codexAdapter.status: 'ok'` when it passes or there is no managed install (this doctor test may stub the shell-out). Separately, an **unstubbed** test invokes **`echoctl doctor` itself** from a **non-repo cwd with a deliberately sparse/minimal `PATH`**, against a **temp-`$HOME` managed install**, asserting `codexAdapter.status: 'ok'` (no false-degrade) — this exercises the full unattended runtime path end to end: doctor resolving the installer by its absolute anchor, invoking it `execFile`-style **with the normalized safe `PATH`** so the interpreter and internal commands (`mktemp`/`shasum`/`git`/`python3`) all resolve, plus `--check`'s own cwd-independent `source` resolution. A sparse `PATH` must yield `ok`, **never** `check-error`. A further case forces an internal check failure (e.g. an unwritable temp location) and asserts `--check` exits **`2`** and doctor reports `codexAdapter.status: 'check-error'` (degraded) — **not** `'drifted'` — with a **non-empty `detail` carrying the stderr/exception reason** (a broken check is both non-drift and actionable). (Running `--check` directly does **not** substitute for the doctor test — it cannot prove doctor's own resolution or `PATH` normalization.) Finally, **remediation-accuracy** cases run **from a non-repo cwd**: (i) a non-default `--namespace <ns>` install with one hand-mutated `SKILL.md` → doctor reports `drifted`, the per-skill remediation line in `detail` is **cwd-safe** (absolute installer path) and carries `--namespace <ns>`, and running that exact line clears the drift (follow-up `--check` exits `0`); `codexAdapter.remediationCommand` is asserted to be an **absolute** path, not a bare relative command. (ii) a **mixed-families** install (a default `ECHO:` skill **and** a `--namespace <ns>` skill, each drifted) → `detail` carries a correct, independently-runnable remediation line for **each** drifted family, and running both clears all drift — proving the per-skill remediation handles mixed families without doctor-side grouping.

## Out of Scope (Don't Drift)

- **Any wiring into `check-coupled-invariants.sh` or a CI/merge gate.** This is the codex-099-consult HIGH and the entire reason for the split — the check is operator-side only. (AC4 enforces.)
- **Auto-repair / `--fix`.** doctor reports and points at the installer; re-running the installer is the remediation. A `--fix` convenience is a separate follow-up if demand surfaces.
- **The Claude adapters** (`.claude/commands/`, `~/.claude/commands/`) — already covered by `sync-skills.sh --check` in the merge gate; not re-checked here.
- **`echo_skill()` render-at-use-time** — endgame, deferred per followups.
- **emit-sidecar.py / the sidecar `producer` field** — that is item 099 (deliverable A); this item is the adapter-freshness half only.
- **New sentinel fields or installer render changes** — `--check` consumes the existing `.echo-managed` sentinel as-is.
