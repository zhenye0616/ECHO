# Canonical echo-context repository, self-contained CI, and source-artifact authority

## Why this spec exists

Item 135 proved that the local echo-context extraction is source-independent and behaviorally faithful, but it deliberately ended with one migration branch, no remote, no install, and no runtime authority. Its extraction-finality tests also bind several checks to the then-current HEAD and two operator proofs default to Project_echo Git objects, so blindly publishing that directory would produce a repository that cannot safely evolve or validate itself in hosted CI.

This first gate makes echo-context/main the canonical source authority without confusing source publication with installation or live-state authority. It preserves the exact reviewed extraction as an immutable baseline, creates the private canonical repository, gives clean clones a self-contained quality gate, and seals one explicitly non-installable source artifact for item 137. Project_echo remains the installed runtime and state authority throughout this item. The third-repository split executed here is authorized by the 2026-07-15 successor-repository execution decision and item 135's founder-reconciled merge; the G2 topology record defined two organization repositories and kept the context layer inside echo-dev-platform until split triggers fired, so it is cited for its controls-preservation rule, not as the split authority.

This internal-asset work is permitted by the scope guard because unified machine context across Codex, Claude Code, and Cursor is required by the current ECHO development workflow and Team-product delivery. It is not a parallel commercial roadmap or a second product.

The tag push is create-only compare-and-swap, never an ordinary push, and its refspec source is the captured immutable object, never a mutable name: it uses Git's empty-expect lease form with the mandatory machine-readable result flag (`git push --porcelain --force-with-lease=refs/tags/v<version>: origin TAG_OBJECT_OID:refs/tags/v<version>`), which atomically requires the remote ref to not yet exist at write time; pushing from the mutable local `refs/tags/v<version>` is forbidden, because a concurrent retarget of that local ref between pre-push verification and the push would silently change what is written (a local-ref-retarget race fixture proves that retargeting the local tag ref after `TAG_OBJECT_OID` capture cannot alter the pushed object), `--porcelain` is mandatory (fixtures reject an invocation lacking it), and the push succeeds only when the porcelain result reports the ref as newly created (`*`); if an identical expected tag appears between the empty-namespace preflight and the push, an ordinary push would report an adopting `up to date` success — here that same-OID pre-existing ref fails the lease and blocks, because the workflow may adopt no ref it did not create, and the run log records the porcelain created-by-this-run proof. Tag verification runs immediately after the push as an authenticated remote readback — reading the remote ref to the tag object to the peeled commit — and fails unless the remote ref resolves to exactly the captured `TAG_OBJECT_OID`, the peeled commit equals the approved source SHA, and the annotation bytes equal the template oracle exactly — a lightweight tag pointing directly at a commit fails. Failure handling distinguishes a surviving controller from hard loss. While the controller process survives — a write whose response was lost or ambiguous, or whose authenticated readback failed or was ambiguous — read-only reconciliation only is permitted: the surviving controller records every attempted write and the last observed destination state in the run log as best-effort diagnostics, makes zero further external writes of any kind — no retry, no repeat write, no deletion, no cleanup, no adoption — and terminates with a nonzero, failed run conclusion for founder disposition.
