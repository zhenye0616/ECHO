Each observation or adjudication is recorded in the migration/evidence record as a fixed secret-free row with a canonical encoding. The encoding is lexically exact, not merely semantic: one UTF-8 JSON object on a single line terminated by exactly one LF, keys serialized in exactly this order — `adapter`, `slot`, `ts`, `generation`, `event_count`, `atom_count`, `verdict` — with no whitespace outside string values, integers in minimal decimal form (no sign, no leading zero except a lone 0, no fraction, no exponent) bounded to at most 2^53−1, and strings using only mandatory JSON escapes, so any two valid rows are byte-comparable and a re-emitted row is byte-identical. The row contains exactly these keys and no others — `adapter` (string from the literal six-adapter enum `fs`, `git`, `granola`, `claude-code`, `codex`, `cursor`), `slot` (non-negative integer index such that the exact (adapter, slot) pair exists in the hash-bound source-slot inventory of the currently active generation's plan; adapter validity and slot existence are never checked independently), `ts` (RFC 3339 UTC timestamp with Z suffix), `generation` (string equal to the currently active plan-bound generation at write time; the row validates against that generation's inventory, and an inventory-hash mismatch with the active plan invalidates the row), `event_count` and `atom_count` (non-negative decimal integers, never strings, fractions, or negatives), and `verdict` (exactly one of observed, disabled-approved, no-activity-approved). The row carries no date field: any calendar-date key (AC10) is derived mechanically from `ts` by America/Los_Angeles timezone conversion at validation time, never author-supplied. Committed rows carry no reason field: reason codes, adjudication rationale, and per-source checkpoint detail stay in the protected local evidence area and are never committed. Event and atom counts are non-negative integers counting only what that adapter captured within the row's own period (a per-row delta, never a cumulative total) and are zero on disabled-approved and no-activity-approved rows; an observed row whose event and atom counts are both zero is invalid — a slot with nothing captured must instead carry a founder-approved adjudication verdict. A committed row containing any key outside this closed set, an unknown enum value, a plan-unknown slot, a malformed timestamp, a generation that is not the active one, or a string, fractional, or negative count is invalid evidence and fails its gate. Committed rows never contain message bodies, file/document contents, titles, prompts, transcripts, token values, raw source names, paths, URLs, account/repository/document identifiers, checkpoint or cursor values, content-derived hashes, raw errors, or other free-form text. The same row schema and forbidden content classes govern AC10's seven-day evidence records. At this point Project_echo context is retained and non-authoritative pending acceptance, not frozen.

Generation G2 begins the daily-use window. The window starts at the first America/Los_Angeles midnight after G2 activation — the partial activation day never counts — and covers seven consecutive complete America/Los_Angeles calendar days in civil time (a DST-shortened or DST-lengthened day counts as one day). Daily continuity evidence is a plan-derived matrix keyed by (generation, America/Los_Angeles calendar date, adapter, plan source-slot index): the calendar date in each row's key is derived mechanically from that row's UTC `ts` by America/Los_Angeles conversion, never author-supplied; the expected key set is exactly the seven civil dates of the window multiplied by the hash-bound source-slot inventory of the active G2 plan (AC1 schema, bound by the AC9 G2 approval) — which materializes stable slots for all six adapters, including explicit slots for disabled adapters, so a plan omitting a disabled adapter fails AC1 plan validation rather than silently shrinking the expected set — and every plan-configured source slot across all six adapters appears exactly once per calendar day, with disabled-adapter slots carrying verdict disabled-approved. Daily-row period semantics are canonical: each civil day is bounded by two durable, DST-aware boundary cuts taken at the America/Los_Angeles midnights that open and close it, each recorded as a UTC instant; a daily row's `ts` is exactly the opening boundary-cut instant — so its derived calendar date is that civil day, deterministically — its counts cover only that slot's capture within the half-open interval from opening cut to closing cut, and the row may be written or finalized only after its closing boundary cut exists durably. A row finalized before its closing cut, or whose `ts` is not the opening cut, fails the gate. Publication is idempotent under crash/retry: a retried write must reproduce the byte-identical row, and two rows sharing a matrix key with differing bytes are an unresolved source failure. The matrix is complete only when it equals the expected set exactly — seven civil dates times the active-G2 inventory cardinality, with no missing, duplicate, or extra key. Any authority rollback, artifact/config generation change, lost history, duplicate capture, auth bypass, or unresolved source failure resets the window, restarting the count from the next America/Los_Angeles midnight.
