A single sourceable `echo_effect <kind> -- <argv...>` wrapper that ALL side-effectful operations route through: `kind ∈ {spawn-agent, codex-exec, push, launchd, review-tick}`. Reads `ECHO_EFFECT_MODE ∈ {live, dry-run, test}` (default `live`). Under `live`: exec the argv as-is. Under `test`: no-op/stub — return a per-kind canned outcome (so a test can drive a runner end-to-end without launching production effects) following the SAME non-live status contract. EXACT non-live status contract (r2 codex F1 / codex-ops F1 HIGH — resolves the two-incompatible-contracts conflict; r3 codex F1 — applies IDENTICALLY to BOTH non-live modes, dry-run AND test, so there is no false-success dry-run-push path): for every `kind` EXCEPT `push`, BOTH `dry-run` AND `test` return exit 0 (a benign no-op success is safe because no caller treats their completion as "the side effect reached origin"). # 079 — Loop Reliability Pack

## Why (the friction this closes)

The multi-agent loop (atomic claim → ephemeral-worktree build → cross-vendor review rounds → watcher disposition → merge-and-cleanup) is the dogfooding infrastructure for the V1 wedge. It works — but Codex's loop-inefficiency analysis surfaced four recurring RELIABILITY frictions that cost founder-interventions and wasted review rounds:

1. **Automation reads/writes the founder's live checkout.** The 050 worktree-isolation invariant says automated runners must never share the founder's live `.git/index` — but the clean-snapshot preamble is COPY-PASTED across `_run_reviewer.sh`, `review-queue-watch.md`, and `merge-and-cleanup.md`, and `combine.py --all` can still commit into the live checkout. Dirty-tree and local-behind friction recur because clean-snapshot is a convention, not the enforced default.
2. **Tests can launch production effects.** Each side-effectful runner (spawn agent / `codex exec` / `git push` / launchd / review tick) reinvents its own stub seam. 077→078 surfaced cases where a test path could fire a real vendor CLI or a real push. The fix is one shared effect boundary with `live | dry-run | test` modes — generalizing beyond `_run_reviewer.sh`'s ad-hoc `command -v` guard.
3. **Review-handoff artifact is synthesized by hand.** The code-reviewer subagent, `/review-pending`, and the codex children all emit "the same review" — but the contract is implicit (the orchestrator greps for the right headings; `merge-and-cleanup` re-scrapes `verdict:`/`reviewed_at:` with awk). Manual sidecar synthesis is where producer/consumer drift hides.
4. **Coupled files drift because the check is prose, not mechanism.** `package.json ↔ package-lock.json` lockfile-miss recurred 077→078; skill-adapter sync, MCP-registration coherence, and manifests are all checklist-driven at `merge-and-cleanup` C5. A mechanical pre-merge invariant checker turns "the human remembered to run it" into a gate.

This is **operating-model reliability hardening** — NOT a new product surface, NOT a new orchestration layer (Codex was explicit). It removes friction from the loop that already exists; it adds no new role, no new coord event, no new MCP tool, no new daemon code.

## Locked scope (what 079 IS)

- **Preserve, do not touch:** atomic claim, reviewer independence, ephemeral worktrees (079 makes them the *default*, not a new mechanism), cross-vendor review, founder-gate-only-at-judgment (substantive-conflict + push-to-main).
- **AC1-AC4 are the load-bearing core** (one per Codex fix 1-4). **AC5 is stretch** (Codex fix 5 — executable patch-drift classification). **Codex fixes 6-7 are deferred siblings** (After-Completion).
- Refactor-to-shared and gate-don't-auto-fix throughout: every change is byte-identical under `live`/production to today's behavior; the new value is enforcement + de-duplication + a validated contract.

## Acceptance Criteria

1. **AC1 — clean snapshots as the default execution substrate.** A shared `tools/review-queue/_clean-snapshot.sh` exposes `echo_enter_clean_snapshot <role-slug>` that performs the 050 preamble (prune → enumerate registered → GC >60min orphans → `git fetch origin main` → require `TMPDIR` → `git worktree add --detach $TMPDIR/echo-<role>-<uuid> origin/main` → export `$WT` + set `ECHO_REVIEW_QUEUE_REPO_ROOT=$WT` → install unified ERR/EXIT cleanup trap). `_run_reviewer.sh` (and, in prose, the watcher + merger skills) source it instead of holding their own copy; the resulting worktree setup preserves the **observable invariants** each caller depends on — detached HEAD at `origin/main`, worktree path `$TMPDIR/echo-<role>-<uuid>`, exported `$WT` + `ECHO_REVIEW_QUEUE_REPO_ROOT=$WT`, trap-discards-on-any-exit — verified per-caller (r2 codex F3: NOT a literal byte-identity fixture across the three blocks, which differ by design in role-slug, cleanup `cd` target, and surrounding context; AC7 asserts the per-caller invariants, not a byte diff). `combine.py`'s git-mutating path **refuses to run against the founder's live checkout** unless the PHYSICAL worktree it is about to mutate is proven to be an `echo-<role>-<uuid>` snapshot (git-toplevel basename match + parent==`$TMPDIR` + registered-worktree membership + physical-path equality with `ECHO_REVIEW_QUEUE_REPO_ROOT`, so a stale env var alone cannot bypass it — r1 codex-ops F6) OR `--allow-live` is explicitly passed, with a clear diagnostic. A test-compat rule (r1 codex F2) keeps the existing 044-autostash temp-clone invocation (`combine.py --repo-root=<clone> --all`) green: the throwaway clone is recognized as not-the-founder-live-checkout (or passes `--allow-live`), and AC7 updates that test to the chosen rule. The founder's live checkout is an operator workspace, never shared automation state. Crash-safe + idempotent (re-fireable; trap discards on any exit).

2. **AC2 — one effect boundary for every side-effectful runner.** A shared `tools/review-queue/_effect-runner.sh` exposes `echo_effect <kind> -- <argv...>` for `kind ∈ {spawn-agent, codex-exec, push, launchd, review-tick}` (J3 kind-label still open for r2), reading `ECHO_EFFECT_MODE ∈ {live, dry-run, test}` (default `live`). `live` execs argv unchanged (production byte-identical); `dry-run` prints + returns without executing; `test` no-ops to a per-kind canned outcome. BOTH non-live modes (`dry-run` AND `test`) follow ONE non-live status contract: exit 0 for every kind EXCEPT `push`, which returns the named non-live sentinel `ECHO_EFFECT_NONLIVE_RC=97` under BOTH dry-run and test (the false-completed-tick guard below depends on this exact carve-out, and the carve-out is mode-symmetric — there is NO dry-run-push-returns-0 false-success path; r3 codex F1). `push-with-retry.sh`'s ENTIRE pull+push cycle (not just the terminal push) and `_run_reviewer.sh`'s child-CLI dispatch route through it. Under `ECHO_EFFECT_MODE=test`, a reviewer-wrapper smoke launches **no real vendor CLI**, and the push helper performs **no real git pull, rebase, or push** (test-asserted — no network I/O, no local git mutation). The 050 refspec, retry, and queue-errors fallback in push-with-retry are all preserved inside the `live` path.

   **AC2 false-completed-tick guard (r1 codex-ops F4 HIGH).** Because `commit-reviewer-response.sh` commits the reviewer response BEFORE calling the push helper, and the reviewer tick runs in an ephemeral worktree that is force-removed on exit, a `test`/`dry-run` mode leaking into a production wrapper would otherwise: create the response commit locally → no-op the push as "success" → emit a `completed` tick → delete the only copy on cleanup, leaving `origin/main` with no `<reviewer>.md`. The effect boundary MUST prevent this: a non-`live` `echo_effect push` returns the **named non-live sentinel exit code `ECHO_EFFECT_NONLIVE_RC=97`** (NOT a `live`-identical exit 0 — `push` is the one `kind` that does NOT return canned-0 under non-live, precisely because its exit is load-bearing for completion semantics), and `commit-reviewer-response.sh` MUST treat exit 97 as a **non-completed / test-only outcome**: on sentinel it refuses before `git add`/`git commit` (preferred) or rolls back the local-only commit, and the reviewer tick MUST NOT emit a `completed` tick when the response did not actually reach `origin/main`. Test-asserted (exact status, not just "distinguishable" in prose — r2): under BOTH `ECHO_EFFECT_MODE=dry-run` AND `ECHO_EFFECT_MODE=test`, `echo_effect push` returns exit 97 (r3 codex F1 — both non-live modes asserted, so a dry-run-push false-success path cannot survive); `commit-reviewer-response.sh` driven through either non-live path produces NO false `completed` queue tick and leaves NO orphaned local-only response commit; and `push-with-retry.sh`'s non-live return propagates 97 through to the caller (the test asserts the exact code through both `push-with-retry.sh` and `commit-reviewer-response.sh`, under both non-live modes). Every NON-`push` kind is test-asserted to return EXACTLY exit 0 under both dry-run and test. The default + production mode is `live`; non-live is a test/diagnostic affordance only.

3. **AC3 — unify the review-handoff artifact.** A canonical `tools/review-queue/schemas/review-sidecar.schema.json` + `tools/review-queue/validate-sidecar.py` pin the COMMITTED sidecar contract — the `backlog/pending_review/<id>.review.md` artifact `/review-pending` Step C WRITES and `/merge-and-cleanup` Step A CONSUMES (NOT the child-review RUN_DIR intermediate, which keeps its internal 8-heading parse step unchanged). The contract is the EXISTING committed-sidecar shape: frontmatter `item_id`/`verdict`/`reviewed_at`/`test_counts` + an **additive** `producer` field, and the body sections matched VERBATIM as `/review-pending` Step C emits them (r2 codex F2 / codex-ops F2): `## Verdict`/`## Pre-merge fixups`/`## Expected merge conflicts`/`## Follow-up items (defer, do not block merge)` (plus `## Open questions for founder` iff verdict is `block`). This is **additive-only** (the lone new thing is the `producer` frontmatter field; the heading TEXT is exactly what the producer writes today, parenthetical included — so the validator never rejects the live artifact) — NOT a format migration, so every existing/next sidecar validates and merge-and-cleanup's Step-A/C section reads keep working. The validator MUST coerce a PyYAML-parsed `datetime` `reviewed_at` back to an ISO-8601 `Z` string before jsonschema validation (r3 codex F2 — the live Step-C template emits `reviewed_at` UNQUOTED at review-pending.md:175, so `yaml.safe_load` yields a `datetime`; without coercion a `{type: string}` schema would reject the live artifact). Validator-side coercion is chosen over producer-quoting precisely to keep additive-only (no producer edit). `/review-pending` Step C stamps `producer`, validates via `validate-sidecar.py` before commit+push (fail-loud on invalid). `/merge-and-cleanup` Step A **consumes the validated artifact** (`validate-sidecar.py` then read `verdict`/`reviewed_at`) instead of ad-hoc `awk` scrapes — regardless of which producer wrote it. Both canonical skills re-synced via `tools/sync-skills.sh`. No producer-specific synthesis path remains. AC7 test asserts a real `/review-pending`-shaped committed sidecar — using the EXACT `## Follow-up items (defer, do not block merge)` heading (parenthetical included) the producer writes (r2) — validates AND then passes merge-and-cleanup's Step-A verdict/reviewed_at reads + Step-C section reads (producer↔consumer round-trip).

4. **AC4 — pre-merge invariant checker for coupled files.** A mechanical `tools/review-queue/check-coupled-invariants.sh` (run from the merger worktree) asserts: (i) `package.json ↔ package-lock.json` coherence (catches the 077→078 lockfile-miss); (ii) skill-adapter sync (invokes `tools/sync-skills.sh --check`); (iii) MCP-tool registration coherence (every `registerX` in `src/mcp/server.ts` has a matching tool file + the registration test recognizes it). Exits non-zero with a per-invariant diagnostic naming the drifted pair. `/merge-and-cleanup` Step C5 runs it alongside `npm test`/`lint`/`typecheck`/`sync-skills --check` and **pauses-don't-auto-fix** on failure. Mechanical at the gate, not checklist-prose.

5. **AC5 (STRETCH) — make review-round patch-drift executable.** A `tools/review-queue/classify-finding-provenance.py` reads a just-combined `combined.md` + the item's prior-round `spec-r*-patches` git diffs and classifies each actionable finding as `original_contract | prior_patch_introduced | propagation_gap` (the exact broad-lookback signal `review-queue-watch.md`'s reframe gate already describes in prose).
