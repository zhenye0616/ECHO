# 087b — Reviewer-child read-only migration (the R1 fix; consumes 087's binding fields)

## Why (the friction this closes)

Today the review AI child runs at `--sandbox danger-full-access` and **commits its own `<reviewer>.md` from inside the child** (`commit-reviewer-response.sh`, invoked by the reviewer prompt). That is the **R1 fabrication surface**: at the 084 review a full-access child wrote a stale/fabricated sidecar, and another child hung after verification and never emitted its review (rc=143, `queue-errors.md`). An AI child that both reasons about a diff AND has commit + full-filesystem + network capability is the wrong trust boundary.

The fix is a **two-actor split**: the AI child reads + reasons + produces review *content* (read-only, no commit); the **wrapper/orchestrator** validates that content and publishes the canonical `<reviewer>.md` (write + commit + push). 085 tried to do this in one spec but contradicted itself (enforce read-only WHILE keeping child self-commit). 087b does it in the right order — **move the commit to the wrapper FIRST, then flip the child to read-only** — and it builds on 087's binding file, which already carries the `agent_sandbox`/`commit_policy`/`expected_artifact` fields for exactly this.

## Locked decisions

1. **The wrapper owns everything except reasoning.** Move out of the child and into `_run_reviewer.sh` (the wrapper): (a) the `<reviewer>.md` write+commit+push (`commit-reviewer-response.sh` becomes wrapper-owned); (b) the coord lifecycle — `tick_start` before spawn, `tick_end` outcome only after the wrapper's own validate→write→commit→push (a content-only child can't know whether publish succeeded — r1 codex-ops F2) — plus post-response journaling; (c) **request selection + bind-validation pre-spawn** (today the child's Step-2 scan-pick produces the `correlation_id`; the wrapper must own selection so it knows which `correlation_id` to emit and can classify the pre-spawn outcomes no-candidate / stale_combined / bind_failed / duplicate_response / upstream_duplicate — r2 codex F3); (d) **git-sync (pull/rebase) + preparing an immutable review packet** fed to the child, so the child performs NO filesystem writes except its stdout (r2 codex-ops F1). The child's only contract: read the packet, reason, emit the review markdown to stdout.
1a. **The read-only child's capture channel is `stdout_json` (an existing 087 `capture.kind` enum value), NOT raw `stdout_text` (r4 codex + codex-ops HIGH, convergent).** Raw `codex exec` stdout interleaves banner / model / workdir / echoed-prompt / token-summary noise with the final answer, so validating it as the review Markdown would either fail schema-validation forever (terminally skipping a healthy child) or publish a contaminated sidecar. Instead the child runs with structured output (`--json` / equivalent), the wrapper redirects stdout to `capture.stdout_path` and **parses the final assistant-message event** as the canonical payload; raw stdout/stderr are kept as diagnostics only. (`codex exec --output-last-message <wrapper-owned capture.final_message_path>` is an equivalent clean-final-message alternative if verified to work under `--sandbox read-only`.) Wiring `stdout_json` is in scope, not a new kind (r1 codex F1 + codex-ops F1; r4 channel correction).
2. **Then flip `agent_sandbox` → `read-only`** for codex + codex-ops in `reviewer-bindings.json` — AND the `--sandbox` token in the binding's `argv`, since 087's gate resolves argv verbatim and the argv is the actual runtime control (a metadata-only flip is theater — r1 codex F2). The child can no longer commit/write even if a prompt regresses — enforced by sandbox, not just prose.
3. **Order matters: the FULL write-free-ification (publish + lifecycle + selection + git-sync + packet-prep all moved to the wrapper, child writes only stdout) lands BEFORE the sandbox flip** within the item. Flipping `read-only` while the child still does any write (self-commit, git pull/rebase, temp-file materialization) loses the review — the 085 trap, generalized.
4. **Fix the stale reviewer-prompt prose in the same pass** (R3): monthly journal shard, no HTML-twin commit. Low-cost, same files.
