## Problem / Why (the friction this closes)

ECHO's reviewer invocation has **two parallel sources of truth and a shell-string execution path**, and the live review child runs at `--sandbox danger-full-access`.

1. **Two config files disagree on the invocation model.** `tools/review-queue/reviewers.json` carries `invoke_command` as a **shell string** (`codex exec -C {{WT}} --sandbox danger-full-access - < {{PROMPT}}`), resolved through `_reviewer_gate.py --print invoke_command` via `shlex.quote` and finally executed as `bash -c "$INVOKE_CMD"` in `_run_reviewer.sh` (line ~168). Meanwhile `tools/review-queue/coord-roles.json` already carries the same invocation as a clean **argv array** (`["codex","exec","-C","{{WT}}","--sandbox","danger-full-access"]`). Two files, two formats, one drifts from the other; the shell-string round-trip is the injection-prone, harder-to-test path. Per the cross-tool protocol, **vendor differences must live in DATA (a binding file), not in skill prose or shell-string templates.**

2. **The review AI child runs at `danger-full-access`.** `docs/review-queue-setup.md` (~line 45,51) blesses `--sandbox danger-full-access` for Codex review ticks. That conflates two actors: the **AI child** (which should only read + reason about a diff) and the **wrapper/writer** (which legitimately commits + pushes the `<reviewer>.md` artifact). A full-access AI child is a real incident surface — at the 084 review a sandboxed Codex child ignored a read-only instruction context and wrote a fabricated/stale sidecar; the escalated child hung after `status`/`diff` and never wrote its output (084 agent_notes + `_followups.md` ~919-922). The structural fix is a **two-actor sandbox split**: the AI child runs `read-only` and NEVER commits; only the wrapper/orchestrator publishes the canonical artifact.

This converged over a **3-round cross-vendor Codex consult on 2026-06-02** (R3 verdict: "YES, spec it, no new gaps"). The full converged contract is larger (normalized capture intermediate, evidence byte-cap/redaction, schema enum-sync codegen, per-binding preflight/smoke, orchestrator-owned sidecar migration). This item is **Codex's "smallest first PR" — behavior-preserving except the sandbox flip** — that lands the load-bearing core (one argv binding file + the sandbox split) and defers the rest to named successors.

## What this is — and what it deliberately is NOT

A **reliability + protocol-hygiene fix** to the cross-tool review substrate: collapse reviewer invocation to ONE argv-based binding file and split the AI-child sandbox from the writer's commit capability. It is NOT a new product surface, NOT a change to the committed review-artifact boundary (`backlog/reviews/<item>/r<N>/<reviewer>.md` stays canonical), NOT the orchestrator-owned-sidecar ownership migration (that's a successor), and NOT a headless-watcher change.

## Locked decisions (founder + 3-round cross-vendor consult, 2026-06-02)

1. **One canonical argv binding file, `tools/review-queue/reviewer-bindings.json` (`kind: reviewer`).** It subsumes the reviewer-relevant parts of `reviewers.json` + the invocation argv of `coord-roles.json`. The entire shell-string path (reviewers.json strings → `_reviewer_gate.py` shlex → `_run_reviewer.sh` `bash -c`) is replaced by argv execution.
2. **Two-actor sandbox split.** `agent_sandbox` (the AI child) defaults to `read-only`; `commit_policy`/`artifact_writer` (the wrapper/orchestrator that publishes `<reviewer>.md`) keeps write+push. The AI child NEVER commits. Flip the live Codex review child off `danger-full-access`.
3. **Behavior-preserving except the sandbox flip.** Reviewer self-commit behavior stays AS-IS for now (the ownership migration off `commit-reviewer-response.sh` is a successor). The committed boundary stays the canonical `backlog/reviews/<item>/r<N>/<reviewer>.md`.
4. **The wrapper-spawn path is in scope as a reconciliation, not a rewrite.** `coord_invoke` spawns `run-<role>-reviewer.sh` (it does NOT exec coord-roles.json argv); 085 makes the spawned wrapper resolve the child argv from `reviewer-bindings.json` so there is exactly ONE invocation source of truth. `coord_invoke`'s own spawn contract (env handoff, fire-and-forget, `reviewer_invoked` emission) is unchanged.
